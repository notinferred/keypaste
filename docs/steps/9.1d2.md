## What changed

- **The 1Password reader** (`Core/Import/OnePasswordCsvReader.cs`), registered in `ExportImport.Readers`, read with 1Password's export guide, which lists the CSV's fields as title, website, username, password, one-time password, favorite and archived status, tags and notes, for Login and Password items only; pass-import's and 2FAS's 1Password importers and their sample exports, which give 1Password 8's header as `Title,Url,Username,Password,OTPAuth,Favorite,Archived,Tags,Notes`, its marks as `true` and `false` and its tags separated by `;`; Bitwarden's 1Password 7 importers; and KeePassXC 2.8's 1PUX reader, `OPUXReader.cpp`, for how KeePassXC carries a favorite, an archived item and a bare TOTP secret. It recognizes a header naming, in any order and any case, `title`, `url`, `username`, `password` and `notes`, and no column but these, 1Password 8's others and 1Password 7's `type`, so 1Password 8's export and the common fields 1Password 7 and earlier write with their labels (`notes,password,title,type,url,username`) are read, and 1Password 7's export of all fields and every other manager's CSV are not; it takes up to 32 MiB. `Url` is the item's web address and `OTPAuth` its TOTP, a link as written and a bare secret made the link D-0574 builds; `Tags` is split on `,` and `;`, as KeePass splits a tag list, and 1Password 7's `type` becomes a tag. `true` in `Favorite` gives the tag `Favorite` and in `Archived` the tag `Archived`, as KeePassXC's 1Password importer tags them (D-0576).
- **Everything that does not land is named.** A row holding nothing is a record of no item; a `Favorite` or `Archived` value other than `true`, `false` or none is named on its item. 9.1a's plan names the rest, such as a TOTP secret `TotpSpec` does not read as written and an untitled item's new title.
- **The CSV readers share** `Core/Import/CsvExport.cs`: the file's records through `Csv.TryRead`, the header's columns, a row holding nothing, the columns a reader does not read, and D-0574's TOTP link. 9.1c's LastPass reader now uses it, with its messages unchanged.

## Limits and follow-ups

- **1Password's CSV holds only Login and Password items**, and of them only the fields above, without their vault, custom fields or attachments, and nothing in the file says an item had any, so the preview cannot name them (1Password's export guide). Its 1PUX export holds them; reading it is 9.1d1. 1Password's desktop apps export no passkeys in either format.
- **1Password 7's export of all fields is not recognized.** Its columns differ by item type, a value can fill several of them, and its Mac app writes a tag list as `{( "a" )}` with backslash-escaped quotes, which D-0573's strict reader refuses; such a file is refused as no export keypaste reads. Exporting the common fields with column labels, or 1PUX once 9.1d1 reads it, is the way.
- **The tag separator** is taken from importers' sample exports, since 1Password's guide does not say it; splitting on `,` as well as `;` means a tag holding a comma, which no KeePass tag can hold, lands as two.
- **1Password 7's type becomes a tag on every item**, `Login` included, as LastPass's note type does (D-0572).
- No KeePassXC gate reads an imported 1Password item; that KeePassXC computes the codes from the `otp` link written rests on its importers building the same link (9.1a's limit).
- The desktop's import of an export is 9.1f.
