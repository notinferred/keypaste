# 9.2a — Read and compute interoperable TOTP in core

Completed 2026-10-21 on `main` at `c208ad6`, source only: ci 39633992142 and app 39633992293, every job green, and ci 39634014306 ran the `tools` jobs.

The founder approved the shape on 2026-10-21: core and tests only, reading KeePassXC's `otp` URI and KeePass 2's `TimeOtp-*` fields, computing RFC 6238 codes with the platform's HMAC, the seed kept out of logs, messages and `ToString`, and no agent release path or app surface, which are 9.2b's.

## Amendments

Under the founder's decision rule of 2026-10-21, these choices the row left open were taken as recommended, founder-delegated:

- **Read order.** `otp` is read when it holds anything, and KeePass 2's fields only otherwise. A malformed `otp` is refused and does not fall back to `TimeOtp-*`.
- **Two KeePass 2 secrets.** Two non-empty `TimeOtp-Secret*` fields are refused rather than one chosen by an assumed order. An empty field counts as absent, as in KeePass 2.
- **Ranges.** A code has 6 to 8 digits. A period is 1 to 86,400 seconds. Unparseable, signed or fractional values are refused.
- **Steam.** `encoder=steam`, in any case, gives 5 characters of Steam's alphabet, with `digits` absent or 5. Any other encoder is refused.
- **Names.** The URI's algorithm is `SHA1`, `SHA256` or `SHA512` and KeePass 2's is `HMAC-SHA-1`, `-256` or `-512`, both in any case. Anything else is refused rather than defaulted to SHA-1.
- **URI parsing.** The scheme, type and parameter names match in any case, and the label, `issuer` and other parameters are ignored. A known parameter given twice is refused, and `otpauth://hotp/` is refused as HOTP.
- **Decoding.** Base32 is RFC 4648 in either case, ignoring spaces and trailing padding. A final group of 1, 3 or 6 characters and any other character, `0`, `1` and `8` included, are refused. Hex ignores spaces, and base64 follows .NET, which ignores whitespace.
- **Not read.** KeePassXC's legacy `TOTP Seed` and `TOTP Settings` pair and KeeOTP's `key=…` form in `otp` are not read, so an item holding only them has no TOTP.
- **API.** `Vault.ReadTotp(name, out refusal)` returns a `TotpSpec` the caller disposes. As `ReadField` does, null stands for both a missing entry and no TOTP, and the refusal says when the TOTP is there but cannot be computed. `TotpSpec.Code` takes a `TimeProvider` or a moment and returns a `TotpCode` with the code and the time remaining.
- **Test seam.** The internal `Vault.SetFieldsUnchecked` writes `otp` into a vault keypaste created, for the round trip the approved shape asked for, because D-0369's name rules refuse `otp` to keypaste's writers. It differs from the `AddProtectedFieldUnchecked` seam D-0369 replaced, which wrote names `SetFields` now writes.
- **`{TOTP}`.** The placeholder still refuses its value (D-0465), and `TimeOtp-*` names stay writable through `set --field`, protected by default.

## Evidence

Nothing was built or run on the founder's machine. Hosted runs are listed at the top.

**Core.** [TotpSpecTests](../../tests/Keypaste.Core.Tests/TotpSpecTests.cs), 19 methods and 100 cases:

- RFC 6238 Appendix B's six times for SHA-1, SHA-256 and SHA-512 at 8 digits, through KeePass 2's UTF-8 `TimeOtp-Secret` and again through `otp` URIs with base32 seeds: 36 codes.
- RFC 4226 Appendix D's counters 0 and 1 at 6 and 7 digits, with the remaining time at a period's start and at half a second before its end.
- A code read from an injected `ManualClock`.
- Steam codes for counters 0 and 1, `GG5F5` and `PV9M4`.
- Seven accepted URIs, covering case, defaults, labels, encoded spaces, padding, extra parameters and a fragment, each computing the code of its plain form.
- 24 refused URIs, each with its exact message, which never holds the seed.
- The same seed in base32, hex and base64 giving one code.
- KeePass 2's algorithm, length and period being read, and 14 refused KeePass 2 fields.
- Four items with no TOTP, and `otp` read before `TimeOtp-*`, its refusal standing.
- The exact field-name match, and `otp` and the four `TimeOtp-Secret` names never leaving by name.
- RFC 4648's base32 vectors, and eight refused base32 texts.
- `ToString` of a spec and a code, a disposed spec's zeroed seed and its refusal, and a moment before 1970.

The Steam expectations were derived by hand from RFC 4226's truncated values with Steam's alphabet and character order as steam-totp encodes them. They come from no published Steam vector and have not been compared with KeePassXC.

[VaultTotpTests](../../tests/Keypaste.Core.Tests/VaultTotpTests.cs), 6 cases:

- The `otp` the foreign-vault fixture writes reads as SHA-1, 6 digits and 30 seconds. After keypaste writes another field of the entry and saves, it computes the same code and is still protected and read-only.
- An `otp` for RFC 6238's SHA-256 seed, on an entry keypaste created, reads back after a save with its algorithm, 8 digits and period, and computes `46119246` at 59 s.
- `TimeOtp-Secret`, `-Algorithm` and `-Length` written through `SetFields` keep the secret protected and compute RFC 6238's SHA-512 code.
- A missing entry and an entry with no TOTP read as none, with no edit and the vault still current.
- A malformed `otp` is refused by name without its seed, and neither the spec nor the code shows a seed or a code.

## Limits and follow-ups

- No KeePassXC gate compares a code: no surface prints one until 9.2b. 9.2b's gate should check its codes against `keepassxc-cli show --totp` on the same vault, Steam included.
- The seed is also held as the field's `string`, read from KeePassLib's protected string, and as the URI's or field's text. Only the decoded bytes and the intermediate buffers keypaste allocates are zeroed, within the limits [SecretBuffer](../../src/Keypaste.Core/SecretBuffer.cs) states.
- `TotpSpec` is not synchronized: a code computed while another thread disposes the spec can come from a partly zeroed seed. That code is wrong, never the seed.
- Legacy `TOTP Seed` and `TOTP Settings`, KeeOTP's form and KeePassXC's repair of `0`, `1` and `8` in base32, if it makes one, are unread or refused. A vault holding them has no code in keypaste.
- Source only. The tests have not run.
