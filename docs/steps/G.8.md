## Amendments

The STEPS row asked that each connected app's row say what the app can see and whether it may run commands, and that the owner apply the intersection with the bridge's flags. The founder widened it on 2026-10-10 while planning the 0.5.0 rows, and answered the questions its design, build, rechecks and review raised.

- **Modes, and the app decides** (founder, 2026-10-10).
  - Each agent's settings say what it can see (project or environment picks, with an advanced field taking `--expose`'s selectors), whether it is given values or "no, only into commands it runs" (the earlier inject-only, now visible), whether it may run commands, and its mode: Ask every time (Allow once only, the earlier `ask`), Ask, allow for a while (Allow once or Allow for 1 hour, the earlier `session`), or Automatic, which releases credentials and listings within what the agent can see with no prompt and still records them. Commands still ask.
  - An agent has a default mode and optional rows per project or environment, from the vault's tags. A project row beats the default, and an item in two projects takes the stricter row. The prompt gains "Always for <project>", which writes a row after the same confirmation. Per conversation is deferred until a bridge has a stable identity.
  - Optional limits, off by default, on the default or a row: at most N an hour and Automatic until a date. Reaching one asks instead of refusing.
  - A newly connected agent keeps today's behaviour: every project (`tag:env:*`), values when approved, no run, Ask, allow for a while. Settings are keyed by the agent's name, which the screen says; an unknown name gets the defaults, and Automatic is never set for `*`.
  - Setup registers bridges with run available and wide reach, so the owner, not the agent's configuration, decides; G.2's row left what setup registers to G.8. Settings that give more live in the vault as ACAF v1 data and are written only by the unlocked owner; `clients.toml` keeps only what narrows, so a hand or script edit can only take access away and a vault restore or merge cannot undo a revocation. Settings travel with the vault, and both owners apply them. `keypaste agent` becomes a full owner that saves widenings confirmed at its terminal, amending D-0382.
  - A change from outside the app comes from `keypaste mcp policy <agent> --mode … [--project …]`, with no new command, or from the agent through a keypaste tool. One that gives more opens the owner's confirmation, Deny focused and armed as the approval prompt is; one that narrows applies at once. Agents' requests fall under T-11's cooldown.
  - Protected environments (D-0348) stay Allow once only: no mode, Always for, limit or row releases them unasked. PRODUCT §2's command rule is unchanged, since commands are never automatic.
  - Saving settings into the database's custom data was to raise the file to KDBX 4.1, with a note the first time; the design answer below replaced that storage, and the file stays KDBX 4.0.

- **ACAF v1, defined inside G.8** (founder, 2026-10-10).
  - The Agent Credential Access Format is a small, versioned, public storage format for agent access in KDBX files, so other KeePass apps can be compatible.

- **Design answers** (founder, 2026-10-12), given on the probe below.

| Case | Result on all three runners |
|---|---|
| A. KeePassXC opens, edits an entry, adds one and saves | Every `acaf.*` key and value kept, the unknown `acaf.v2.*` too; every tag kept. **The file is rewritten as KDBX 4.0 and every item's modification time is dropped.** KeePassXC adds its own `_LAST_MODIFIED` item (and on 2.7.12 a `KPXC_RANDOM_SLUG` padding item). |
| B. keypaste changes ACAF and a tag in copy k; KeePassXC edits an entry in copy x | Entries merge correctly **both directions** (k's tag change and x's edit both survive). ACAF: merging x into k keeps k's set; **merging k into x keeps x's older set** (keypaste's newer `ask`, its added agent and its removal all lost). |
| C. Two keypaste copies change different agents | Either direction: "Database was not modified"; **the target keeps its own whole set and the other change is lost.** |
| D. keypaste narrows `claude-code` to `ask` in a copy KeePassXC had saved; merge with the older copy | Older into newer keeps `ask`; **newer into older leaves the older `automatic`.** |

KeePassXC merges the database's custom data as one whole, taking the source's set only when the source's own `_LAST_MODIFIED` is newer than the target's. A file without that item, as keypaste writes, gets the time KeePassXC opened it, and keypaste's later changes leave a stale one in place. So KeePassXC drops ACAF's item times and KDBX 4.1 and mis-merges ACAF data kept there, while tags and entries are sound, which is why the founder chose entries.

## What changed

- **What applies to a request** (`Core/Agents/`). `AgentAccess` holds one agent's settings, with `AgentMode`, `ProjectScope` and `AccessLimit`. `EffectiveAccess` decides per item from the least of the bridge's arguments, every record under the agent's name and this computer's ceilings: what it can see, values, run, and the mode of the item's environment row, else its project row, else the agent's, the strictest across its tags. A protected environment is Allow once only, `*` and an unnamed bridge are held beneath the defaults and never Automatic, and a spent or ended limit asks. `HourlyLimit` carries `PolicyRateLimiter`'s sliding hour, counted per agent and row in the owner process, kept across locks and lost on restart. `UntilTime` reads an end on this computer's clock, a date ending at the close of that day, and sends UTC.
- **Settings in the vault, as ACAF v1** (D-0442, D-0449).
  - `AcafRecord` reads and writes the JSON in each entry's `acaf` field. A part it does not understand is read at its narrowest (mode Ask, values and run off, seeing nothing; an empty or unreadable limit reads the mode as Ask), and the record then applies only beneath the defaults. A change patches only what it names, keeping every other member and row as stored.
  - `AgentAccessStore` keeps one hidden entry per agent in `ReservedGroups.Agents`, `.keypaste/agents`, under the RFC 9562 version 5 UUID `AcafIds` derives from its name in ACAF v1's namespace; `.keypaste` and `.keypaste/agents` get the UUIDs their paths derive. A record applies only as the file holds it, and beneath the defaults while the open vault differs from its file. Every entry under one name reads at the least of them and is given the same record on a write. A write moves the agent's entry back from the recycle bin or another group, first copies an entry retitled into another agent's name for that name, drops a tombstone for the UUID, and finds the entry by its title when another object holds the derived UUID. Reset writes a defaults record, a record of another version is never rewritten, a root group whose own name is `.keypaste/agents` is ignored, and an edit whose save fails is taken back out of the open vault. `KeePassInterop` and `Vault` gained the internal seams these need.
- **This computer's ceilings**. `AccessCaps` and `AccessCapsSource` replace `ClientPolicies` and `ClientPolicySource`. A `clients.toml` row has `label`, `project`, `mode`, `values`, `run`, `see`, `per_hour` and `until`, each only a ceiling; an agent with rows of its own is held to them, any other to the `*` rows. The earlier `policy = …` form is malformed and refuses every agent request, as an unreadable file does. The file holds up to 2048 rows and 256 KiB and is refused before it is written past either. Every change goes through `AccessCaps.TryChange`, which re-reads the file at write time under an in-process lock and `clients.toml.lock`, so ceilings written while a confirmation is open survive it.
- **Judging a change**. `AccessEdit` turns the CLI's, the panel's and the agent's words into one change, and `AccessChange` counts its gains by what the agent can do before and after it, under the narrowing answer above. A change lifts what the ceilings hold back only where it names it, and a confirmed widening lifts them exactly as far as it gives.
- **The owner** (`ApproverHandler`, `SessionAuthority`, `ApprovalGate`).
  - A values-off agent's credential request and a run-off agent's run are refused before anything is resolved. A listing (`NamesRequest` now carries `ClientLabel`) and a run reach only what the agent can see.
  - Automatic releases with no prompt, under its own audit method, and never seeds the grant cache.
  - Always for allows the request once, keeps the gate's one-at-a-time slot, asks to make that environment Automatic with no end, and once the release has left tells the person where they answered when the change did not take effect and why (`AlwaysForNotice`).
  - Agents' settings are listed and changed over the pipe. The pipe accepts the origins terminal and agent only; the app's settings and Always for are in-process origins no pipe request can claim. An agent-origin request must name the label its connection attached as, meets the bridge's rules again, and may not reset or remove a limit.
  - Every request for more from a terminal or agent shares one cooldown; narrowings never cool.
  - Every settings change is recorded under the tool `access_change` before the reply, and a change whose line cannot be written is not made.
  - `Core/Policy/` and `ClientPolicies*` are deleted.
- **Audit**. The methods `automatic`, `run-off` and `narrowing` are new; nothing writes `policy` or `policy-limit` again, and History still reads such a line from `v0.3.0`. History says "Changed settings" only for a change that was made, "Asked to change settings" otherwise, and shows a settings end on this computer's clock with its offset and its seconds when they are not zero.
- **CLI**. `keypaste agent` opens the vault through `VaultSession.OpenHeld`, applies the vault's settings, names at start each agent on Automatic and where and an existing `policy.toml` as no longer read, offers `[a] always for`, confirms a change at its terminal where only `y` allows, saves it under its claim, and prints when Always for did not take effect, with the exact retry command when the names are plain. `keypaste mcp policy` lists every agent, asking the owner in turns, with `--json`, and changes one with `--project`, `--mode`, `--see`, `--values`, `--run`, `--per-hour`, `--until` and `--reset`; with nothing holding the vault it only lowers ceilings. `keypaste env tag` names the agents a tag would put an entry in Automatic reach of before its y/N. `keypaste policy`, its listing and `keypaste agent --policy` are gone.
- **Bridge**. Every bridge offers `request_access_change`: `mode`, `project`, `see`, `values`, `run`, `until`, `per_hour` and a required `reason`, about its own `--client-label` only, refused without asking anyone on a bridge with no label, checked by the bridge and again by the owner (`AccessChangeRules`), and answered CHANGED or NOT CHANGED, a change made but not recorded being told so. With nothing holding the vault, the bridge applies an agent's narrowing to the ceilings `--clients` names, or its home's when its `--audit-log` is its home's, and records it. `--clients` is a new option. `ToolText`'s out-of-scope and no-approver refusals and `request_credential`'s description, which G.8 made false, are corrected, and the run-off and inject-only refusals name the new tool.
- **Setup and Connect** register every bridge with `--allow-run` and `--expose '**'`; globs the person gives replace `**`, so they only narrow, and a custom home also pins its ceilings as `--clients` (D-0446, D-0389).
- **App**.
  - Each agent card's Settings button opens `AgentSettingsView` below the cards, replacing the card's ⋯ menu: mode, values, commands, Can see as All projects or Only these with Advanced patterns and a warning when nothing is picked, project rows, and limits with a date picker and a time of day. It also says when this computer holds the agent back, with "Use the vault's settings", and when settings apply only beneath the defaults. `*` offers no Automatic and no commands.
  - `AccessChangeWindow` confirms a widening in a fixed layout, Deny focused and Allow armed after one second: the agent, what it gains with hidden characters shown escaped, the limit an Automatic would have, the origin the request claims, and a reason in the approval prompt's inert box, or where the person chose the change.
  - The approval prompt has a fixed 34px slot for Always for, so Deny and the allows never move. `NoticeWindow` says when Always for did not take effect, with a button that opens that agent's settings.
  - A tag change in the item pane, Projects or Recommendations names the agents Automatic for the project it adds the entry to. The Agents status names each agent on Automatic and for what. Reset of a `clients.toml` keypaste cannot parse goes through the owner's confirmation and sets the file aside under the next free `clients.toml.unreadable` name. The item pane's Agent access card follows what an attached agent can see, and the organize forms' notice speaks of place patterns.
