# G.1 — Let agents and the CLI use the vault the person chose

Completed 2026-09-30 on branch `task/g1` above `a432ade`, source only; dev runs 36729191981, 36733010645, 36736785187, 36740705295 and, after review, 36745527472 and 36745718152.

## Amendments

The row was not detailed when selected, so it was expanded against the code before building:

- **Build.** `VaultLocation.TryResolve` takes a third source: `--vault`, then `KEYPASTE_VAULT`, then the `vault` key of `app.toml` (`AppSettings.Vault`, read by `ChosenVault`), and otherwise refuses with ``no vault chosen. Open one in the keypaste app or run `keypaste use <path>`; --vault <path> or KEYPASTE_VAULT names one for a single command.`` Every CLI verb that resolves a vault through `VaultLocator`, and `keypaste-mcp` at startup, use it. The app records the vault at the first create or unlock when none is chosen and says so once in the shell's notice; Settings › Agents and the CLI shows the choice and Use this vault changes it. `keypaste setup` and the app's Connect write `--vault` only for a vault other than the chosen one: one named on setup's command line or in its environment, or, in the app, the unlocked vault. The choice is a path in `app.toml`, never read from the vault and never a secret.
- **Verify.** Resolution precedence in core, CLI and bridge tests; setup's registrations and output; the app's first-unlock record, Settings and Connect; and `verify-connect-client.sh` extended so the shipped bridge registered with no `--vault` finds the chosen vault through the app's Connect check, a pinned registration still reaches the app while another vault is chosen, and `keypaste use` and `keypaste grants` read the choice without `--vault`.
- **`keypaste use [<path>]` was added** so the CLI can show and change the choice without the app; the outcome named choosing "via the CLI" and the refusal needs a next step a terminal-only person can take. The CLI does not record a vault on `init`, `import` or `agent`: only the app's first create or unlock does, as the row said, and a script run without `KEYPASTE_HOME` therefore never changes a person's choice.

## Limits and follow-ups

- **A running bridge keeps the vault it started with.** Changing the choice reaches a client's bridge when the client restarts it; `keypaste use` and Settings say so.
- **`keypaste import <file>` now copies into the chosen vault** when one is chosen and neither `--vault` nor `KEYPASTE_VAULT` is set, as it did for a named vault; `--in-place` keeps the old behavior.
- **`keypaste init` with no path** now targets the chosen vault and is refused because it exists; with none named or chosen it asks for the path to create.
- **A path holding a quote, a control character or, outside Windows, a backslash** cannot be written in `app.toml` and is not recorded; Settings and `use` say that path cannot be recorded.
- **THREATS** T-3 and T-36 name the chosen vault among what a spawning process or an agent editing its configuration can set, and T-29 states that resolution never consults which vault is held and names what records a choice; T-10 still places same-user adversaries out of scope.
- **macOS.** Four `EnvLaunchThroughAppTests` cases fail on macOS on every branch, the defect the integration branch holds as F.28 (dev run 36732743823), so no macOS run of this step reached the session gates; FEATURES names that gap.
- G.2 builds on this: it registers every client without `--vault`.
