# 9.1e — Import KeePassXC's CSV export

Completed 2026-10-28 on `t6-csv`, source only; runs pending.

## Amendments

The founder decided on 2026-10-28 that the items KeePassXC's CSV export takes from its recycle bin are left behind, as a KeePass file's import leaves them, and named in the preview as not imported because they were in the recycle bin, where this step had first landed them under `Recycle Bin (imported)`; D-0577 says so. The row is otherwise as selected, under 9.1a's contract and the founder's conventions of 2026-10-28 (9.1d2's record lists them). The selection asked for `Group` to map to the folder path keeping KeePassXC's root-group naming: KeePassXC's export writes the database's root group as the first name of every path, and the reader drops it whatever it is called, so an item lands in the folders a KeePass file's import of the same database gives it, which the founder accepted the same day.

## What changed

- **The KeePassXC reader** (`Core/Import/KeePassXcCsvReader.cs`), registered in `ExportImport.Readers`, read from KeePassXC's `CsvExporter.cpp` at 2.6.6, 2.7.6 and 2.8.0, which write the same ten columns, every field quoted: `Group`, `Title`, `Username`, `Password`, `URL`, `Notes`, `TOTP`, `Icon`, `Last Modified` and `Created`, one row per item of every group, the recycle bin included, the root group's items first. It recognizes a header naming the first six as KeePassXC spells them, reads the other four when present and names any other column holding a value; it takes up to 32 MiB. `Group` is the root group's name followed by the item's groups, `/` between them; the root's name is dropped and the rest split as KeePassXC's own CSV import splits a path, an empty name skipped. A row whose first group below the root is `Recycle Bin`, the group KeePassXC deletes into, is no item. `TOTP` is the `otpauth://totp/` link KeePassXC builds from the item's settings (`Entry::totpSettingsString`), which lands in `otp` as written. `Last Modified` and `Created` are Qt's `ISODate` in UTC and become the item's own times (D-0577).
- **Everything that does not land is named.** Each item of the recycle bin, by its path, because it was in the recycle bin; an icon other than `0`, KeePass's key, which every imported item gets; a time not written as KeePassXC writes one, the import's time taking its place; a column keypaste does not read; and a row holding nothing. A group named `Recycle Bin` deeper down lands as 9.1a's plan lands one, as `Recycle Bin (imported)` with its note.
- **The import gate** (`scripts/verify-keepassxc-import.sh`) gains a CSV round trip: KeePassXC imports a second seed, two items in its root group and one in `Work/Dev` with a username, URL, notes, an 8-digit `otp`, icon 12 and its own times, deletes one root item into its recycle bin and exports the vault with `keepassxc-cli export -f csv`, whose CSV holds it under `Root/Recycle Bin`; the shipped CLI imports the CSV under `kpxc-csv`, naming the icon and the recycled item; KeePassXC sees `kpxc-csv/csv-top` and `kpxc-csv/Work/Dev/csv-site`, no `Root` group and no recycled item, and its CSV export of the target gives each item the row its export gave it, TOTP and times included, but for the icon. The negative control shows the row comparison sees a changed field.

## Limits and follow-ups

- **KeePassXC's CSV carries only an item's standard fields, TOTP, icon and times**: no custom fields, attachments, history, tags, expiry, Auto-Type or passkeys, and nothing in the file says an item had them. `keypaste import` of the `.kdbx` itself keeps them (D-0356).
- **The recycle bin is known by its English name.** The CSV does not say which group is the recycle bin, and KeePassXC names it in the language it runs in, so a translated one's items land under a group of that name; a group of the root that a person named `Recycle Bin` is left behind with it.
- **A group name holding `/`** reads as two groups, and a root group with no name makes its first subgroup read as the root, since KeePassXC's export joins names with `/` unescaped.
- **The root's name is dropped whatever it is**, where KeePassXC's own CSV import drops only `Root`: a database whose root has another name, as KeePass 2 and a translated KeePassXC give one, lands its groups directly under the import's group here, and under a group of the root's name when KeePassXC imports the CSV.
