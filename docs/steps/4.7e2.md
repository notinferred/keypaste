## Amendments

The founder-approved plan of 2026-10-18 set the upgrade semantics (its choice 5), which D-0462 records. Implementing them added four details:

- **The Trash.** The old bundle is moved to the Trash by Finder, through Apple Events, as a person deletes an app. A shell `mv` into `~/.Trash` is not used, since that folder is privacy-protected.
- **No quarantine.** The upgrade's copies carry no quarantine. The install leg holds Gatekeeper's refusal (D-0461), and this leg holds what an upgrade keeps.
- **The unlock.** The upgraded app's unlock is judged: it may rewrite only `app.toml` and `recent.toml`, and the transitions after it compare with what it left.
- **Settings on Linux.** The Linux leg now sends its Settings chord through `shortcut`, which sends the same `ctrl+4`.

## Limits and follow-ups

**What the runs cannot establish.**
- These are rehearsals of unsigned candidates on one runner image, not release evidence.
- No person replaced the app by dragging the new one onto `/Applications`, so Finder's replace dialog was not exercised. The administrator dialog that Settings' Link raises was not exercised either.
- Open at login's LaunchAgent is checked as a file. No login loaded it.

**Left behind by an uninstall.** The `/usr/local/bin` link and the LaunchAgent, which name the removed app, are left. Unlike the Linux link, both are in the comparison, so the uninstall check requires them unchanged. They stay by founder decision 2026-10-22, and [desktop](../desktop.md#removing-keypaste) gives the commands that remove them.

**Unverified until 3.5b.** Once a signed bundle has run, macOS may refuse a job's replacement of `/Applications/keypaste.app` without App Management permission. Finder, which the job already drives, is the likely route. By founder decision 2026-10-22, 3.5b's acceptance reruns this job's macOS leg on the first signed bundle to check it.
