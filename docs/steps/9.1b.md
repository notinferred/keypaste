# 9.1b — Import Bitwarden's JSON export

Completed 2026-10-28 on `t6-bw` in `e1bd05ca` on `t6`, source only. At `8aabcf52`, ci 40777892604 and app 40777907585 passed every job on all three runners on their first attempt.

## Amendments

The founder's brief for this batch added a KeePassXC check that KeePassXC reads an imported item's `otp` and `KP2A_URL_n` as keypaste wrote them, which [9.1a](9.1a.md) left to the first reader. It extends `verify-keepassxc-import.sh` rather than the `verify-keepassxc-fields.sh` 9.1a named, since that gate already covers `keypaste import`.

After the first build, the founder decided on 2026-10-28 that an import carries passkeys, where the step had named every passkey as not imported, and accepted the `Favorite` tag, Bitwarden's English labels and protection where Bitwarden masks as built. D-0369 is amended in place to let an import write KeePassXC's passkey fields, D-0571 says how a passkey lands and D-0570 names only the passkeys after an item's first. The amendment also gave `keypaste --help` its export line. The founder decided the same day that an archived item gains the tag `Archived` in every export reader, where the step had named the archive as not imported; D-0569 and D-0570 say so. The row is otherwise as selected.

## What changed

- **The reader** (`Core/Import/BitwardenJsonReader.cs`, registered in `ExportImport.Readers`). The format was read from Bitwarden's own source at `bitwarden/clients` `c35c09ff` (2026-10-28): the export models in `libs/common/src/models/export/`, the JSON types and export services in `libs/tools/export-vault-core/`, the item, field, linked-field and match enums, and the item views that say which details are masked; and the TOTP parser in `bitwarden/sdk-internal` `5c0b59ae`, `crates/bitwarden-vault/src/totp.rs`. It recognizes a JSON object whose first member is `encrypted`, or `folders`, `collections` or `items`, and reads up to 64 MiB. An account-restricted or password-protected export is refused, saying to export again with the `.json` format; a structural surprise refuses the file naming its place, such as `items[0].login.username is not text`, never a value (D-0568).
- **What lands** (D-0569). Every item type Bitwarden exports, login, secure note, card, identity, SSH key, bank account, driver's license and passport, lands under its folder or, in an organization's export, its first collection, each nested on `/`. A login's username, password and first web address land in their places and the rest in `KP2A_URL_n`, through 9.1a's plan. Its TOTP lands in `otp`: an `otpauth://` URI as written, and a bare base32 secret, as Bitwarden shows Google's, or a `steam://` one as the URI KeePassXC's own Bitwarden import makes, without spaces or padding, so keypaste, KeePassXC and Bitwarden compute one code. The other types' details are custom fields under Bitwarden's labels, protected where Bitwarden's view masks them: a card's number and security code, an identity's Social Security and passport numbers, an SSH private key, a bank account's number, PIN, SWIFT code and IBAN, a license number and a passport's numbers. A custom field keeps its name, plain when text or boolean and protected when hidden. A favorite gains the tag `Favorite` and an archived item the tag `Archived`, and each earlier password is a version at its `lastUsedDate`.
- **Passkeys** (D-0571). The contract gains `ExportPasskey` on `ExportItem.Passkeys`, and the plan writes an item's first in KeePassXC's `KPEX_PASSKEY_CREDENTIAL_ID`, `_PRIVATE_KEY_PEM`, `_RELYING_PARTY`, `_USERNAME` and `_USER_HANDLE`, all protected, tags the item `Passkey` and names the rest. The reader converts each Bitwarden passkey as KeePassXC's own Bitwarden import converts it, read from `keepassxreboot/keepassxc` at 2.7.10, 2.8.0 and `develop` `0491ec6f` (`src/format/BitwardenReader.cpp`, `src/core/EntryAttributes.cpp`, `src/browser/BrowserService.cpp`, `src/browser/PasskeyUtils.cpp`), and reads a credential id in Bitwarden's `b64.` form as Bitwarden's `credential-id-utils.ts` does, where KeePassXC's import reads only a GUID.
- **What is named** (D-0570): passkeys after an item's first, in one line the landing passkey's counter, site and display names, discoverable flag and creation date, which KeePassXC has no field for and its own import drops silently, a passkey whose credential id or key does not decode, linked fields, the master password re-prompt, match detection, further collections, unknown folder and collection ids, an undated earlier password, empty folders and collections, items in the trash, unknown item types, any member keypaste does not read, and the attachments the export leaves out.
- **The CLI.** `keypaste --help` and `keypaste import --help` name exports, the latter with the formats it reads and `--skip-existing`; a wrong operand count asks for a KeePass database or export file.
- **The gate.** `verify-keepassxc-import.sh` imports a Bitwarden export holding a bare lowercase secret with spaces, an otpauth URI with SHA-256 and 8 digits, a `steam://` secret, three web addresses and KeePassXC's own Bitwarden test passkey, compares `keepassxc-cli show --totp` with `keypaste get … totp` inside one period for each, reads the URL, `KP2A_URL_1`, `KP2A_URL_2` and the five `KPEX_PASSKEY_*` attributes back with `keepassxc-cli show -a`, the passkey's as KeePassXC's `testBitwardenPasskey` expects its own import to write them, and fails when two items' codes match.

## Limits and follow-ups

- **One passkey per item**, as KeePassXC keeps; the rest are named, as are the landing passkey's counter, site and display names, discoverable flag and creation date, which KeePassXC has no field for. keypaste itself still uses no passkey (BACKLOG 8.5), and whether KeePassXC signs in with an imported one is not exercised here; KeePassXC uses passkeys from 2.7.7, so Ubuntu 24.04's 2.7.6 only reads the fields.
- **Encrypted exports are refused, not decrypted.** KeePassXC decrypts a password-protected one; keypaste asks for the plaintext `.json`, which the person should delete once imported.
- **Bitwarden's `.zip` export with attachments is not read**, and is refused as before as no KeePass database. Its `data.json` is the export this reader reads.
- **Codes Bitwarden computes that keypaste does not** are named rather than carried: Bitwarden computes TOTP codes from an `otpauth://hotp/` URI, digits up to 10 and parameter names in any case, where `TotpSpec` refuses them (D-0498).
- **History holds passwords only.** Bitwarden keeps no earlier username, address or notes, so each version carries the current ones, and a hidden field's change, which Bitwarden records in password history as `name: value`, lands as an earlier password.
- An item in several collections lands once; the field labels are English.
