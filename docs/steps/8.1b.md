Completed 2026-10-29 on `t6-sodium` in `4325f151` on `t6`, source only. At `34564a1a`, ci 40909948638 passed every job on all three runners on its first attempt, and app 40909966048 on its second: its first failed desktop tests (macos-15) in `DrawnMaskTests`, which F.73 holds, and only that job was rerun.

## Amendments

- **Which release.** The row's "pinned stable release" is libsodium's latest point release, 1.0.22 of 2026-04-09. Upstream's rolling `libsodium-1.0.22-stable.tar.gz` is replaced in place, last on 2026-10-28, so no SHA-256 pin can hold it and an older commit could not rebuild; its changes since 1.0.22 are speed, a misuse handler no longer run under the library's lock, and build tooling (D-0612).
- **A way into the binary.** Before 8.1c's relay nothing in `keypaste` calls the box, so NativeAOT would trim it away and the linker would take nothing from libsodium's archive. `keypaste --selftest` runs the known answers in the binary, and CI requires it of every NativeAOT `keypaste` it builds (D-0613).
- **A shared library for the tests.** Tests run in the .NET runtime, which cannot call a static archive, so the build also makes a shared library from the same release, loaded only by its full path beside the binary (D-0612).
- **The TweetNaCl.js fixture** was sealed on a runner by a temporary step in the first class run, removed before integration; nothing ran on this machine but the compile check.

## What changed

- **The build** (D-0612). [build-libsodium.sh](../../scripts/build-libsodium.sh) fetches libsodium 1.0.22's release archive from GitHub through `fetch-pinned-asset.sh` at its SHA-256, checks its Minisign signature and the signature over its trusted comment under upstream's key with OpenSSL 3 (Homebrew's on macOS), requiring a changed hash to be refused, and builds on the target's own runner: configure and make on Linux and macOS, with `MACOSX_DEPLOYMENT_TARGET` 14.0, and on Windows `cl` over all 141 sources with the settings of upstream's ReleaseLIB project, `lib` for the archive and a DLL linked from the same objects that exports the four functions keypaste calls. It writes `libsodium.a` or `libsodium.lib` and the shared library to `artifacts/native/<rid>/`, stamped as `build-argon2.sh` stamps its file.
- **`src/Keypaste.Browser`** (D-0611). `Sodium.cs` is the only file that imports libsodium: `sodium_init`, `crypto_box_keypair`, `crypto_box_easy` and `crypto_box_open_easy`. Its resolver, in a build in the .NET runtime, loads the shared library only by full path from `AppContext.BaseDirectory` and otherwise throws, so no system libsodium answers. `NaclBox` is the key pair, the seal and the open, checking nonce and key lengths and returning no message for a box that does not verify; `BoxKeyPair` holds the secret key in a pinned array zeroed on disposal. `KnownAnswers` holds NaCl's box vectors from libsodium's `test/default/box_easy.c`, `box2.c` and `box_easy.exp`, and the TweetNaCl.js fixture; `BrowserEntry.SelfTest` is the project's one public member.
- **The link** (D-0612). `Keypaste.Cli.csproj` references the project and declares `DirectPInvoke` for `libsodium` with the archive as a `NativeLibrary`; a NativeAOT publish stops before compiling when the archive is missing. `Program.cs` hands `keypaste --selftest`, alone, to `BrowserEntry` before any verb.
- **CI** (D-0613). `publish-desktop-bridge.sh` builds libsodium, publishes, and requires the copied `keypaste` to pass `--selftest`, so app.yml's package job checks the NativeAOT binary on `ubuntu-24.04`, `macos-15` and `windows-2025`, and `upgrade-desktop.yml` and `build-upgrade-candidates.sh` build it too. ci's aot job and release.yml's build job build libsodium before publishing, run `--selftest` and refuse a libsodium file beside `keypaste`. `verify.sh` builds it before backend's whole run and before a class of `Keypaste.Browser.Tests`, which `dev.yml` maps; app.yml's push paths gain `src/Keypaste.Browser/**` and the script, which `WorkflowRulesTests` asks of a project the consistency tests compile.
- **Records.** `keypaste.slnx` and `release-targets.json`'s shared projects list the project; THIRD_PARTY_NOTICES gives libsodium's ISC notice; README's native build runs the script first; ARCHITECTURE gains the project.

## Limits and follow-ups

- **linux-arm64** is linked only by release.yml's build job, which runs on a tag; no run before a release links or tests that target.
- **Upstream's own test suite** (`make check`) is not run, as libsodium's MSVC project builds none; the box vectors from that suite are what the tests and the binary check.
- **The Windows flags** are upstream's ReleaseLIB project's, given to `cl` directly rather than through its Visual Studio project, which names one toolset version per Visual Studio release; a new libsodium release's project must be read again for changed settings.
- **The shared library** on Linux and macOS is libtool's and exports libsodium's whole API; only the Windows DLL is limited to the four functions. Only `Sodium.cs` calls any of it (`SodiumSourceRulesTests`).
- **No threat** is added: nothing outside keypaste reaches the box until 8.1c's relay, which records its own.
- A new libsodium release changes `VERSION` and `SHA256` in the script; the key stays until upstream changes it.
- Source only.
