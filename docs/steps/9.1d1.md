# 9.1d1 — Import 1Password's 1PUX export

Completed 2026-10-28 on `t6-1pux` in `a63909ac` on `t6`, source only. At `aab473b0`, ci 40797849788 and app 40797861076 passed every job on all three runners on their first attempt.

## Amendments

The founder's brief for this batch added to the row the conventions of 2026-10-28 (a favorite becomes a `Favorite` tag and an archived item an `Archived` tag, a field is protected where the source masks it, every item and field lands or is named in the preview with why, even where KeePassXC's own importer drops it, a taken name is kept beside the other or skipped, deleted or trashed items are left behind and named, and no plaintext temp file, the archive read in memory), and asked that attachments come in through V.8a's cap, section fields become custom fields, the first TOTP land in `otp` with the rest named, passkeys land as 9.1b's do, and a zip bomb be guarded against by caps on the compressed and unpacked size and the entry count and by refusing a path that leaves the archive. A 1PUX export holds no passkeys: 1Password leaves them out on purpose, so none can land, and every import names them as not imported. The row is otherwise as selected.

## What changed

- **The reader** (`Core/Import/OnePassword1PuxReader.cs`, registered in `ExportImport.Readers` after Bitwarden's). The format was read from 1Password's own description, "About the 1Password Unencrypted Export format" (support.1password.com/1pux-format, read 2026-10-28); KeePassXC's 1PUX import, `src/format/OPUXReader.cpp`, its `testOPUX` in `tests/TestImports.cpp` and that test's `tests/data/1PasswordExport.1pux`, at `develop` `0491ec6f`; Bitwarden's `onepassword-1pux-importer.ts` and its types at `bitwarden/clients` `258039a7`; and Proton Pass's 1PUX reader and types in `ProtonMail/WebClients` `df5c7ae7` (`packages/pass/lib/import/providers/1password/`), which gives the `trashed` state and `files/<documentId>__<fileName>` as KeePassXC's does. It recognizes a ZIP archive named `.1pux`, or one whose first entry is `export.attributes`, `export.data` or under `files/`, so Bitwarden's `.zip` export is still not recognized, and takes up to 256 MiB (D-0582).
- **The archive** is opened by .NET's `ZipArchive` over one copy of the buffer `ExportImport` hands over, zeroed when the reader returns, and nothing is extracted. Before it is opened, the reader reads the end of central directory and ZIP64 records itself and counts the headers that follow each start they give without allocating, refusing more than 10,000 entries, so `ZipArchive` never reads a larger directory; it then refuses a path that is absolute, names a drive or climbs out with `..`, and two entries at one path. `export.data` is unpacked only when declared at most 128 MiB, a file only when declared at most 5 MiB, and nothing when the two together declare more than 512 MiB; each entry yields exactly its declared length or refuses the file as damaged, and the attachments already unpacked are zeroed when a later one does (D-0583).
- **What lands** (D-0582, D-0584). Each vault is a group, below its account's name when one file holds several accounts. A login's designated username and password, a Password item's `details.password`, its title, web addresses (the first the item's URL, the rest `KP2A_URL_n`), plain notes, tags, times and earlier passwords land in their places; its category becomes a tag under 1Password's name, its favorite and archived marks the tags above. A web form field without a designation lands as a custom field under its form name, protected when its type is `P`, where KeePassXC's import leaves it out. A section's fields land as KeePassXC names them, `<section>_<field>`, or the field alone in an untitled section; a field named `username`, `password` or `url` fills the item's own while it is empty, and any other name the item already has, a standard field's or KeePassXC's lands as `name (2)`. Concealed values and card numbers, which 1Password conceals, are protected; dates land as `YYYY-MM-DD`, months as `YYYY-MM`, an email as its address and provider, an address on three lines as KeePassXC joins it, and an SSH key as its private key, protected, with its public key, fingerprint and type. The first TOTP lands in `otp`, a bare secret as D-0574's link. A Document's file and each file field land as attachments through 9.1a's plan, which holds them to V.8a's 5 MiB.
- **What is named** (D-0585): an item in Recently Deleted, left behind; each TOTP after the first; a web address's own label and autofill setting; a field that links another item; a field kind keypaste does not read; an item's icon and Watchtower exclusions; a vault's description and icon; an attachment whose file is missing or over 5 MiB, the latter never unpacked; a file no landing item holds; an earlier password with no time; an unknown category or item state; any member the reader does not read that holds anything; and passkeys, on every import.
- `ExportSource.AttachmentTooLarge` is the plan's reason for an attachment over the cap, which the reader gives for one it does not unpack.

## Limits and follow-ups

- **Passkeys do not come across.** 1Password leaves every passkey out of a 1PUX export so that its private key is never written in plaintext; 1Password for iOS exports them only through Credential Exchange, which keypaste does not read. The preview says so on every import.
- **One TOTP per item**, as keypaste and KeePassXC compute one; each further TOTP is named, where KeePassXC's own import keeps it in `otp_1` without computing it.
- **No group icon or description, and no item icon.** A vault's icon and description and an item's icon are named; keypaste writes no custom icon or group notes.
- **Section titles become part of the field's name**, as KeePassXC names them, so a field in a titled section reads `Security_PIN`; an untitled section's field keeps its own name. The founder may prefer a plainer name.
- **A category becomes a tag on every item**, `Login` included, as D-0576 tags 1Password 7's type.
- **A file over 5 MiB** stays in 1Password; save it from there and attach a smaller copy, or keep it outside the vault. **An archive over 256 MiB**, more than 10,000 files or 512 MiB unpacked is refused whole, since the reader holds it in memory.
- **The unpacker's own buffers** (the inflater's window) are freed by .NET rather than zeroed, as `JsonDocument`'s are; the archive's copy, `export.data` and the attachments are zeroed.
- The format's members beyond 1Password's description were taken from KeePassXC's, Bitwarden's and Proton Pass's readers and KeePassXC's test export; no export from a 1Password app was read, and no KeePassXC gate reads an imported 1PUX item.
