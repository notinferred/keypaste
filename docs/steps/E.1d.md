## What changed

- **The planner** (`Core/Launch/TerminalLaunch.cs`). On macOS, `TryPlanThroughSession` plans `/usr/bin/open -b com.apple.Terminal` on the bundle's `Contents/Resources/keypaste-launch.command`, naming no command, directory, project or value. `open` gets the app's environment less every variable whose name starts with `KEYPASTE_`, through `SystemProcessRunner`'s exact environment, and nothing on its input, not even an encoding's preamble.
  - The run's argv is Linux's fixed `sh -c` script with the command as its last argument; Open terminal uses the open script.
  - `ClaimProblem` holds a claim to the owner's project and directory rules, a valid environment name, and Terminal's open script or its run script around one line of at most the 4096 characters a mapping holds. The app checks it before the card, and the owner before it issues a pass.
  - Before anyone is asked, the planner refuses a directory that does not exist and a blank command, as on Linux.
  - `TryPlan` refuses on macOS, so no path hands a released set to `open`.
  - `ForThisMachine` plans through the launcher of the bundle the app runs from. Without that launcher and the bundle's `Contents/MacOS/keypaste`, it reports the caption "This copy of keypaste opens Terminal only when it runs as keypaste.app. Copy the run command instead."
- **Request files** (`Core/Launch/TerminalRequests.cs`). Each run is one owner-only file in an owner-only `keypaste-launch` folder of the per-user temporary folder, read with `confstr(_CS_DARWIN_USER_TEMP_DIR)` as the launcher reads `getconf DARWIN_USER_TEMP_DIR`.
  - The file is created exclusively under a `.partial` name and renamed into place. Its name starts with the time it was written.
  - It holds the format line `keypaste-launch 2` and one field per line: pass, home, vault, endpoint, temporary folder, project, environment, directory, kind and command. Each line is printable ASCII, every byte outside it and every backslash written as `\0` and three octal digits, so a path holding a line break still takes one line. It holds no value.
  - A write refuses a link or file in the folder's place, and throws on a pass without a pass's shape or a field that is empty or holds U+0000. Each write first deletes requests older than a pass lasts.
- **Launch passes** (`Core/Approval/LaunchPasses.cs`). A pass is 32 random bytes in base64url. It is spent at its first presentation, refused after two minutes, bound to its unlock and session, and forgotten with the lifetime that owns the store. `LaunchClaim` holds the project, environment, directory, argv and the card's preview, and no value. `EnvRequest.Launch` travels as `launch`, and decoding refuses anything but 43 base64url characters.
- **The owner** (`Core/Ownership/SessionAuthority.cs`). `IssueLaunch` issues only while the card's lifetime is live, and `WithdrawLaunch` removes a pass. `ReleaseEnvAsync` takes the pass right after admission, and holds a request carrying one to its claim instead of to the command-line length the prompt shows whole.
  - It refuses unasked, and records, a pass that is unknown, spent, expired or another unlock's, or one presented with a request that differs from the claim.
  - It refuses as changed a set whose names, source items or protection changed.
  - Otherwise it releases without asking, and records the release through G.9's `RequestRecorder` as `prompt` with the reason `<N> variable(s), confirmed in the app`.
  - It neither stores a timed allowance nor touches the cooldown, and a protected environment's set is released once.
  - `Unrecordable` and `Sendable` give the app the owner's own History-line and one-reply limits. `keypaste agent`'s owner holds an empty store, so it refuses any pass.
  - `ReleaseTokenEnvAsync` refuses a token's set that `Unrecordable` refuses before release and before any live question, after the token's protected-environment check. An agent's run over its own items budget is refused with the reply as the reason.
- **Frames and lines** (`Core/Infrastructure/MessageFramer.cs`, `Core/Ipc/ApproverProtocol.cs`, `ApproverListener.cs`, `ApproverClient.cs`, `Core/Audit/AuditLog.cs`). The listener writes a reply carrying a set, to `keypaste run --session` or `--token`, as one frame of up to 8 MiB, which only the CLI's `ApproverClient` reads that wide; every request and every other reply stays one 64 KiB frame, and the framer clears the buffer it rented. One audit line holds up to 64 KiB, which the writer's tail window and the verifier read back at 256 KiB. A `run --session` or `--token` line names up to 62 KiB of item names, and an agent's run line keeps 2 KiB.
- **The CLI** (`Cli/Commands/RunCommand.cs`, `RunWithToken.cs`). `keypaste run` takes its project by `--project <name>` or `--project=<name>` in every run mode, whose value is taken whole even when it starts with `-`; an operand and the option together, or two operands, are refused as more than one project, as is either with `--env-file`. With `--session`, a present `KEYPASTE_LAUNCH` must have a pass's shape, or the run exits 2 before connecting. A well-formed pass is sent, and the run prints the starting line once the set is released. A run carrying a pass that is refused before its child starts waits for Return when its input is a terminal, and one that finds nothing answering, the app having locked or quit, says so and to press Run in the app again. Every child `keypaste run` starts loses `KEYPASTE_LAUNCH`, under `--token` and `--bundle` too.
- **The copied run command** (`App/ViewModels/CopiedRunCommand.cs`, `EnvProjectViewModel.cs`, `EnvSetsView.axaml`). The Projects screen's run command and Copy name the project by `--project=<name>` when the name starts with `-` and quote any name holding more than ASCII letters, digits, `_`, `.` and `-`.
  - On macOS and Linux the name goes in single quotes, and a name holding a single quote or a typographic one is written `--project=` with each run of such quotes alone in double quotes.
  - On Windows the name goes in double quotes. A project whose name holds `$`, a backtick, `!`, `%` or a double quote, typographic ones included, has no run command: the card hides the command and Copy and says why in their place, and the screen's copy helper copies nothing for it.
- **The launcher** (`packaging/macos/keypaste-launch.command`, POSIX `sh`).
  - It finds `../MacOS/keypaste` from `$0`, never from PATH.
  - It claims the oldest request by rename, reads it with `IFS= read -r`, and deletes it before running anything.
  - It refuses an unknown format, a malformed pass and an unknown kind, and decodes the remaining fields with `printf '%b'`, refusing any escape but `\0` and three octal digits. A refusal prints its reason and, when its input is a terminal, waits for Return before it exits.
  - It changes to the directory with `cd --` and `exec`s `keypaste run --session --vault … --approver … -p <environment> --project=<project> -- /bin/sh -c <fixed script> keypaste <command>`, with `KEYPASTE_HOME`, `TMPDIR` and `KEYPASTE_LAUNCH` set.
  - `build-macos-app.sh` copies it into `Contents/Resources` with mode 0755, and its check on the unzipped bundle requires it executable and byte-identical. `verify.sh` shellchecks it.
- **The launch endpoint** (`Core/Ownership/LaunchEndpoint.cs`). Each unlock's authority is built with `SessionServer.Build` before any endpoint is bound, and `SessionServer.Bind` binds the vault's. On macOS `SessionHost` also binds a `LaunchEndpoint`, a pipe named `keypaste-launch-` and 16 random hex digits, picked once per host and bound at each unlock, whose `ApproverListener` answers only an attachment and an env request, ending a connection that sends any other kind unanswered, and numbers its connections apart. An attachment there names no client, and an env request goes to `SessionAuthority.ReleaseLaunchAsync`, which refuses unasked, and records, one carrying no pass. Each endpoint's failure to bind is reported apart, a socket error included, and the lock ends both.
- **The app.** `SessionHost` and `AppAuthority` issue and withdraw passes, returning the launch endpoint's name, and `AppAuthority.LaunchFailure` says why that endpoint does not answer the live unlock and `AuditFailure` why the owner's audit log does not open, tried through the owner's own opener. `ProjectLaunching.ForThisMachine(authority)` composes the macOS case, and `ForMacBundle` serves the tests and the gate. On macOS, `ProjectLaunchViewModel`:
  - before the card, checks the plan, the owner's claim rule (`TerminalLaunch.ClaimProblem`), that the launch endpoint answers, whatever agents meet, that the audit log opens, and the History-line limit;
  - shows the same card;
  - after Start, checks the one-reply limit, issues the pass under the lifetime the card was answered in, writes the request, and runs `open` off the UI thread with a 10-second limit;
  - withdraws the request and pass when `open` fails.

  The claim and the request take the environment the card resolved. A started launch outlives the card, as on Windows and Linux. The caption binds the planner's reason. On every platform the card shows a command of up to 4096 characters whole and wraps its directory line; Windows and Linux are otherwise unchanged.
- **The gate.** `Keypaste.AppDriver hold` takes `--terminal-bundle` and a `terminal <run|open> <project> <directory> [command]` line that presses Run in a terminal or Open terminal, then Start. `verify-run-session.sh` gains a macOS leg, written for bash 3.2, in which real Terminal runs the launcher of an assembled bundle, and a later window Terminal opens is checked for any `KEYPASTE_` variable and the master password.

## Limits and follow-ups

- **Not yet observed.** A downloaded, quarantined bundle's launcher and Gatekeeper's handling of it are unverified until 4.7e. Real Terminal has run only an assembled bundle's launcher; an installed bundle's waits for R.1a.
- **What the gate does not see.** It types nothing into Terminal, so Open terminal is checked through its card, the run's launch line and its audit line, not through the interactive shell. The gate also sends the window's CLI output to a file, so the window's own text is checked only through the stand-in in `EnvLaunchThroughAppTests`. ScreenRenderer's new frame `49-env-terminal-unavailable` compiles but is drawn only when `KEYPASTE_SCREENS_OUT` is set.
- **Terminal only.** macOS opens only Terminal, not another terminal app, kept by founder decision 2026-10-22 (D-0451, D-0515): another terminal takes Copy run command. A copy not running as `keypaste.app` opens none.
- **The pass.** A window must ask within two minutes of Start. Until it does, a process running as the person can present the pass first (T-42, outside scope under T-10).
- **macOS-only refusals.** Before the card: a set naming more than the 62 KiB of item names one History line holds and a Run while the app's audit log will not open, named with the log's error, which Windows and Linux now refuse too since every Run writes its line (D-0496) (`1b16a9ca`; ci 39785584625, app 39825609666 at `d57aa9b7`); and, on macOS alone, a launch endpoint the app could not bind, which means no local connection can be opened as this user at all, and macOS naming no per-user temporary folder. After Start: a set over the owner's 8 MiB reply, which macOS could not start a program with anyway, and a Run whose line the owner cannot write to a log that opened, such as on a full disk, which it refuses (T-6) and no check short of writing a line can foresee.
- **The copied run command's shells.** On Windows a project whose name holds `$`, a backtick, `!`, `%` or a double quote has no command to copy, because no quoting keeps such a name whole in Command Prompt, PowerShell and Git Bash at once; Run in a terminal still runs it, and renaming the project gives it a command.
- **After 1.0.0.** `fish` is not on any runner, so the copied run command is never pasted into it, while D-0453 and THREATS.md T-1 say the line is safe there: `EnvProfilesTests` adds `fish` only when it is on `PATH`. Add a Linux-only step to app.yml's `desktop` job, `bash scripts/apt-install.sh --no-install-recommends fish`, before the verify step; Linux suffices, since `CopiedRunCommand` has one branch for every platform but Windows. `EnvProfilesTests`' copied-command cases must then paste each line into `fish` on `ubuntu-24.04` and find `keypaste` given the project whole.
- **History by platform.** Every Run writes a History line and shows in its items' activity: on Windows and Linux the app's authority writes the line a macOS Run's pass writes, before the terminal starts, and starts nothing it cannot record (founder, 2026-10-21, D-0496) (`1b16a9ca`; ci 39785584625, app 39825609666 at `d57aa9b7`).
- **PATH and environment.** A macOS run's command resolves through the person's login shell's PATH, not the app's. A Terminal the app starts keeps the app's environment less every `KEYPASTE_` variable, which holds no value, for every window until it quits.
- **A Windows TxF failure, closed by [F.63](F.63.md).** In ci 38560217331 at `782c6a7`, the first attempt's job 115839155986 (windows-2025) failed `AtomicReplaceTests.A_commit_replaces_the_vault_with_what_was_written` with `IOException`, "The function attempted to use a name that is reserved for use by another transaction", thrown from KeePassLib's `IOConnection.OpenWrite` on a `KeePass_TxF_….tmp` file. F.63 found that the test committed outside the save gate, so a save in another test class could hold its temporary's 8.3 alias, and a probe on `windows-2025` refused 20 of 20 commits with that error while a `KeePass_TxF_` move was held; on Windows KeePassLib commits through Transactional NTFS and never reaches the atomic replace the class tests, so the test now skips there.
