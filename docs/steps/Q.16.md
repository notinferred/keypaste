# Q.16 — Read in any language and region

Implemented 2026-11-05 on `q16-language-and-region`, source only; no package has been installed and no person has run it under another language. Runs are under Evidence.

## Amendments

The founder set the scope on 2026-11-05: the desktop app only. `InvariantGlobalization` lifts for the desktop; the CLI, the bridge, the relay and every other front end stay invariant, so their matching and output do not change. The operating system's ICU is used, with invariant behaviour where it is missing, and none is bundled. Dates, sorting, right to left and strings moved to resources, in English. No language is added and no translation is planned. Security prompts' copy and layout, and the terms' text, stay as they were.

## What it does

The desktop and its test and driver hosts run with a real culture; everything else stays invariant under `Directory.Build.props`. `Globalization/PersonTime.cs` is every time a person reads: the log, Trash, Last used, an item's dates, backups and the status line follow the culture's own patterns and calendar, and with no culture to follow, or for a date outside that calendar's range, read as ISO 8601. A range guard is needed because `ar-SA`'s Um Al-Qura calendar stops at 1900 and 2077 and `DateTime.ToString` throws beyond them, on a date a KDBX file can hold. `TableSorting.CompareText` adds `CompareOptions.NumericOrdering`. Views read 794 uses of 553 labels from `Resources/Strings.resx` through `x:Static`, so a missing one fails the build, as do the menu commands, the table heads, the places in the sidebar, relative times, the file dialogs' titles and the reveal button, and a test fails on a literal word in a view. Windows run right to left when the system's language reads that way; `KpIcon` mirrors only what points a way, the Back chevron among them.

## Decisions

- **The audit.** Every culture-sensitive call in Core, Infrastructure and the desktop now says which it means, and the build holds it: CA1304, CA1305, CA1307, CA1309, CA1310 and CA1311 as errors, with Meziantou.Analyzer's MA0002, MA0011, MA0074, MA0075 and MA0076 for what they miss, chiefly an interpolated number and an unstated comparer. A first pass looked clean and was not: the SDK silences CA13xx under `InvariantGlobalization`, so `src/Directory.Build.props` lifts it for the two libraries, where it reaches the analyzers and no runtime configuration. Each interpolated string became `Invariant(...)`, which is what it produced under invariant globalization, so the CLI's output is unchanged.
- **`ToUpperInvariant` means two things.** A sweep of every BMP character under both modes found it turning U+017F, the long s, into S with ICU and leaving it without, and `OrdinalIgnoreCase` agreeing in both. Core and Infrastructure ban it and every overload that reaches the same casing, through `src/BannedSymbols.OneUpperCase.txt`, for `InvariantUpper`, which leaves the long s, used by `RunRequestRules`, `VaultIdentity` and the 1Password reader. `ToLowerInvariant` agrees and stays.
- **KeePassLib runs in the process too.** It sorted tags with a culture's comparison before writing them, which a probe under `de-DE` showed ordering them differently from the CLI, and read a KDBX 3.1 date with `DateTime.TryParse` under the current culture, though the same probe read an ISO date with its `T` correctly under `ar-SA`, `th-TH` and `fa-IR`. The new `KEYPASTE_INVARIANT_TEXT` guard makes its parsing, comparing and casing invariant or ordinal on the paths keypaste calls, as UPSTREAM.md lists, and skips Windows' `StrCmpLogicalW`, so a vault's tags are written in one order on every platform. A vault saved on Windows before this keeps its old order until it is next saved. With the guard removed, `CultureAgreementTests` under `de-DE` fails on a saved entry's tag order and on a vault and token written under `th-TH` and read under `tr-TR`, which took 1m 40s to fail and is the five-minute hang an earlier attempt at this control mistook for a hung build.
- **A machine with no ICU.** On Linux .NET ends the process at its first use of a culture when libicu is missing, and no runtime setting changes that to a fallback. `IcuFallback.Apply` runs first in `Main`, tries to load libicuuc and libicui18n over .NET's range of versions, and sets `System.Globalization.Invariant` if neither loads, before anything has read a culture. That machine reads ISO dates and sorts by code point ignoring case, with numbers as text, as `--selftest` reports and `verify-no-icu.sh` checks in the real invariant mode. An environment variable in `AppRun` would have covered only the AppImage and not the tar.gz.
- **Words stay left to right in a mirrored window.** With no translation, a right-to-left paragraph turns "24 hours" into "hours 24", which a first frame showed. So under right to left every window mirrors, and each `TextBlock` and each non-mono `TextBox`'s text keeps left-to-right order, right-aligned in its place. A date in a right-to-left culture carries a right-to-left mark at each end so its parts stay in order inside that text; Avalonia draws isolate characters as missing glyphs, so marks are what works. A translation into a right-to-left language drops that half.
- **What a person can reach.** Someone whose system language is Arabic, Hebrew, Persian or Urdu gets the mirrored layout with English words and their culture's dates, including the Hijri calendar under `ar-SA`. Nobody else sees right to left. This follows the selection's "follows the culture"; `ReadingDirection.Of` is the one place to restrict it to languages with a translation, and that is the founder's to choose.
- **A selected row's bar is a border under right to left.** An inset shadow does not mirror, and a negative offset drew only arcs at its corners, so every right-to-left row holds a 2 wide border, which the selected one colours and the sidebar, segmented and group lists keep clear. A table row's own top divider gives way to it, so Trash and Advanced lose the lines between rows under right to left.
- **Prompts keep left to right.** `PromptWindow` sets it and its class `prompt-window` exempts its text from the alignment above, since every window's style key is `Window` and a selector on the subclass matches nothing. A test holds every prompt and the terms window pixel-identical in English and under right to left, and About and the notice window keep left to right too since they share the class. Their copy did not move: `ApprovalWindow`, `EnvApprovalWindow`, `RunApprovalWindow`, `PairingWindow`, `PairingNoticeWindow`, `AccessChangeWindow`, `TerminalEditWindow`, `LockedNoticeWindow` and `TermsWindow` hold no resource, and a test says so.
- **A generated class, checked in.** `dotnet format` reads the sources with nothing built, so MSBuild's strongly typed output was invisible to it and failed the format job. `scripts/generate-strings.py` writes `Strings.cs` from the file and a test holds the two equal. It is plain property reads over `ResourceManager`, with no reflection beyond what the manager does. Time to the first window on a fresh home, published `linux-arm64` in `ubuntu:24.04` under Xvfb here, median of 14 starts: `main` 237 ms with no ICU, this branch 241 ms with no ICU, which is every failed load `IcuFallback` tries, and 272 ms with libicu74 and `en_US`, against `main`'s 258 ms with the same library present and unused. About 15 ms; Windows and macOS were not timed.
- **The log's Time column is 84 wide, not 64,** since "12:04:05 PM" does not fit 64; that is Q.15's least width changed. Trash's time trims with a tooltip where a culture's date outruns its column, as a long date under `ar-SA` does. `LogRow.When`, the full stamp, stays invariant as data a person copies, as do `ChainVerdict`'s record times, Agents' until fields and every file.
- **A secret never meets a format.** Only `UseText` formats a resource, with counts, and a test holds that and that no binding formats a value through one.

## Limits and follow-ups

**Not every word moved.** The task's estimate was at least 600 labels in views; the views held 553. About 1430 string literals that read as words remain in C#, mostly view models' status lines and errors, and Core's messages stay in Core since the CLI reads them. Many interpolate, so each needs reading for a secret before it becomes a format, and the long frames show them unlengthened. The founder allowed stopping here; none of it is translated either way.

No person has used a screen reader, an input method or the OS's own right-to-left controls against this. The native menu, the tray and macOS's window buttons are the system's, and nothing here checks how they mirror. A window's drag and a table's grip under right to left have only run headless. Avalonia, Yubico's SDK and Tmds.DBus run in the process and were not audited; T-52 says so. Letters cased after .NET's Unicode data fold only where ICU knows them, also in T-52.
