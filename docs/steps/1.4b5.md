## What changed

- **Revoking** (D-0629, D-0630). `TokenStore.Revoke` and `RevokeId` take the time and, for an unexpired token, write a newer version of its record with an empty password and a `revoked` member in its notes, the token's version kept in its history; a token past the expiry its notes record is purged at once. Creating and revoking also purge every revoked record whose notes say its token has expired. `TokenStore.TakeBack` purges a creation whose save failed, which the app's Scoped tokens used `RevokeId` for. `keypaste token revoke`'s help now says it stops a token working rather than that it deletes one, and the desktop guide says the same.
- **Reading.** A record carrying `revoked`, or whose UUID the vault also holds a tombstone for, reads as revoked: not listed, `Unknown` to `Verify` and its name free. `Vault.ReadTombstoned` and `ReadSavedWithTombstones`, internal, name the entries `ReadEntries` returns whose UUID has a tombstone, the second under the same saved-state check as `ReadSaved`.
- **The merge** (D-0631). `KeePassInterop`'s merger leaves out of the result every entry either copy keeps in `.keypaste/tokens` whose UUID either copy holds a tombstone for, before the ordinary rules, so neither a later change nor the file holding the record beside its tombstone keeps it. `VaultMergeReport.TookFromOpenCopy` says so for a result that drops such a record from the file.
