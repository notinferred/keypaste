Completed 2026-10-18 at `04cb899` on `task/4.7e1`, as a rehearsal (D-0433): ci 39183363474 and app 39183371580, then install-desktop 39184357594 of that app run's DMG (sha256 `af937544832df7a9f69dbda594154adb841a31e272ee6ddb812b413d38e9bda6`) and upgrade-desktop 39184359968 at that commit. None of it is release evidence. The integrated commit differs from that tree only in this record.

## Amendments

The founder approved the plan of 2026-10-18, which settled the questions 4.7e's row left open:

- **The split.** 4.7e became two children: 4.7e1, the install leg and the Gatekeeper observation, and 4.7e2, the upgrade leg and the macOS upgrade candidates. 4.7e stays the parent that 4.7c2 needs.
- **Evidence.** The evidence is rehearsals, with no candidate tag. 4.7c2 runs both legs on the 0.5.0 tag's signed candidate, so the osx-arm64 branch of `verify-desktop-candidate.sh`'s attestation check first runs there.
- **Gatekeeper.** It is checked on the install path. If assessments are disabled, the leg runs `spctl --global-enable`, and a runner on which they stay disabled records the check unassessed.
- **The launcher.** The quarantined launcher is a recorded diagnostic, not a check, and 3.5b's row now requires the launcher of a signed download macOS opened to reach Terminal.
- **The project run.** It is the CLI's `keypaste run` act, as on Windows and Linux.

Implementing the plan changed four of its details:

- The driver's calls are bounded by `perl`'s `alarm`, not by `lib/common.sh`'s `bounded`, which discards the command's exit status that each act records.
- `lib/macos-install.sh` is sourced by the install exercise alone until 4.7e2 needs it.
- The leg does not look at Privacy & Security. The probe found no Open Anyway there for a refusal that calls the app damaged.
- The check does not require that no keypaste process starts. A refused copy starts translocated and stopped, so the check requires no window, and no process once the dialog is declined.

The probe script and the job were deleted.

**The runner.**
- macOS 15.7.9 (24G830), image `macos15 20260907.0337.1`, Terminal 2.14.
- System Integrity Protection is disabled, and `spctl --status` reports assessments enabled.
- `bash` on PATH is the stock `/bin/bash` 3.2.57.
- `sha256sum` is `/sbin/sha256sum`, and there is no `timeout`.

**The bundle.**
- Its apphost is ad-hoc signed (Identifier `apphost`, no sealed resources).
- `codesign --verify --strict` and `spctl -a -t exec` both refuse it: "code has no resources but signature indicates they must be present".
- `syspolicy_check distribution` reports that codesign error, a missing notarization ticket and an internal XProtect error.

**Quarantine.**
- `NSURLQuarantinePropertiesKey`, given a web download by Safari, writes `0081;…;Safari;…` on the DMG, the flags `release.yml` writes by hand.
- The attached volume mounts with `quarantine`, and its files show no attribute.
- Each of the 260 entries `xattr -lr` lists under the `ditto` copy carries the DMG's quarantine. On a Finder duplicate, the bundle and its executable, the only two paths read, carry it too.

**Gatekeeper.**
- Opening the `/Applications` copy through LaunchServices starts a translocated `keypaste-app` that stays stopped (`T`) with no window.
- CoreServicesUIAgent shows "“keypaste” is damaged and can’t be opened. You should move it to the Trash." and "Safari downloaded this file today at <time>.", with Cancel and Move to Trash.
- amfid logs that the file "is adhoc signed or signed by an unknown certificate chain".
- `open` does not return while the dialog stays, and once Cancel is pressed no keypaste process remains.
- Privacy & Security showed "Allow applications from: App Store & Known Developers" and nothing about keypaste, so it offers no Open Anyway.

**The launcher.** The diagnostic plants a request that the launcher would claim:
- With the bundle quarantined, Terminal did not run the launcher, and CoreServicesUIAgent showed "“keypaste-launch.command” Not Opened" ("Apple could not verify “keypaste-launch.command” is free of malware…"), with Done and Move to Trash.
- After `xattr -dr`, Terminal ran it.

**Driving the app.**
- Through System Events, a walk of the window took 5 to 28 seconds, and Avalonia's controls listed no actions, so an AXPress through System Events found no button to press.
- The accessibility API called from JXA works when attribute names are passed as NSStrings (a JavaScript string is refused with -25201) and elements are passed back as JXA returns them. It walked about 140 elements in 100 ms, and `AXUIElementPerformAction` with `AXPress` pressed every button the session needs.
- An app started by `open` received the caller's `KEYPASTE_HOME`.

**The link.**
- Settings reads the link's state once and caches it, so a link made with `sudo` after Settings shows Link leaves Link offered.
- Pressing Link then finds the copy linked and returns without asking for an administrator (`MacCliLink.Link`), and Settings shows "A terminal runs this app's keypaste from /usr/local/bin/keypaste."

**The baseline.** Before any change, app 39174835494 at `a6b7655` and that commit's rehearsals passed on Windows and Linux: install-desktop 39175664707 and upgrade-desktop 39174837666. Neither workflow had run since G.8 changed both exercise scripts.

## What changed

- **`scripts/drive-desktop-macos.js`, new.** It drives the app through the accessibility API, and System Events supplies keystrokes and another process's dialogs.
  - It keeps the Linux driver's actions, output and exit contract.
  - Its window screenshot is taken by window number, and the colours are counted from that capture.
  - It never presses Move to Trash.
- **`scripts/lib/macos-install.sh`, new.**
  - It quarantines through the API, attaches and detaches, opens the quarantined copy and records what Gatekeeper shows, runs the launcher diagnostic, and starts and quits the app through LaunchServices.
  - A failed detach is kept with `lsof`'s output and never retried past (F.64).
- **`scripts/exercise-desktop-install.sh`.**
  - The macOS platform runs install, then `gatekeeper`, the launcher diagnostic quarantined, the override, and the diagnostic cleared.
  - The session follows, with the Settings link made by `sudo` while Settings offers it, and the terminal check through `/usr/local/bin/keypaste`, whose target must be the installed app's `keypaste`.
  - `OUT` is made absolute on every platform, because LaunchServices starts the app from `/`.
  - The script runs under bash 3.2: no associative array, a tab constant in patterns, and a `shasum` fallback.
  - 28 macOS cases join the self-test, which now re-runs itself with the interpreter it runs under.
- **`scripts/exercise-desktop-upgrade.sh`** runs under bash 3.2 (`tr` for case, `wc -c` for size), though it has no macOS leg until 4.7e2.
- **`scripts/lib/terminal.sh`** holds the macOS login-zsh probe and `mac_cli_link`, which `scripts/verify-macos-cli-link.sh` now uses with unchanged behaviour.
- **`scripts/lib/desktop-drive.sh`** gains the macOS branch and `shortcut`, which sends Cmd on macOS and Ctrl elsewhere.
- **`install-desktop.yml`** gains the macos-15 row, with no `mapfile` and a `shasum` fallback.
- **`verify.sh desktop-gates`** on Darwin runs both exercise self-tests under `/bin/bash`, and app.yml's push paths now include the exercise scripts.

## Limits and follow-ups
