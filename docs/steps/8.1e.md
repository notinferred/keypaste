# 8.1e — Install and remove the host per browser

Completed 2026-11-13 on `t6-host`, source only.

## Amendments

- **keypaste's own extension.** The row as selected took over KeePassXC's host, `org.keepassxc.keepassxc_browser`, keeping a copy to restore. KeePassXC 2.8.0's `NativeMessageInstaller.cpp` counts a browser as on whenever that manifest or Windows value exists and rewrites it at each start, so a KeePassXC still set up would take the browser back. By the founder's direction of 2026-11-13, ratified in PRODUCT v1.26, keypaste answers only its own extension under the host `com.keypaste.browser`, and never writes KeePassXC's; the replaced-manifest copy and its restore left the row. `BrowserIdentity.cs` names test IDs until H-0029 supplies the stores' (8.1f and 8.1g build and publish the extension).
- **Discovery.** By the same direction, each browser's status also says whether the extension is installed in any of its profiles, read from their folders without changing them.
- **Tests write only into temporary folders and a throwaway `HKCU\Software\keypaste-tests\<guid>` branch**, given to Core's `HostPlaces`, the app driver and the fake browser; the shipped binary reads no redirect.
- **Replacing another program's manifest** under keypaste's name: `keypaste browser on` replaces it and names the program it replaced, and Settings asks first, since nothing puts it back. Turning off leaves it.

## What changed

- **Core** (`Browser/`). `HostPlaces` holds where each browser reads its user-level manifest and keeps its profiles, from the platform's variables; on Windows the key's default value under Chrome's, Chromium's, Edge's or Mozilla's `NativeMessagingHosts` names a file under `%LOCALAPPDATA%\keypaste\NativeMessagingHosts\`, and Brave reads Chrome's, so the two turn together. `HostManifest` writes the manifest allowing only the three builds and reads one back as keypaste's only when it is byte for byte what keypaste writes. `HostProgram` names the `keypaste` a terminal finds: the one beside the app, which is the MSI's per-user copy or the bundle's, `~/.local/bin/keypaste` on Linux, made when absent, or the CLI's running binary. `BrowserHosts` reads each browser's status, turns it on and off, and re-points a manifest naming a `keypaste` that is gone or another bundle's at each start of the app. `ExtensionPresence` looks for the extension in Chromium-family `Extensions/<id>` folders and Firefox's `extensions/<id>.xpi`.
- **The relay** answers keypaste's extension's three builds and no longer KeePassXC-Browser's; the confirmation, the countdown and `keypaste approve` name keypaste's extension.
- **CLI.** `keypaste browser` lists the five browsers, who answers each and whether the extension is installed, with `--json`; `keypaste browser on|off <browser>…` turns them.
- **App.** Settings › Browser fill lists the five browsers with Turn on or Turn off, in the menus too, and each start of the app keeps the manifests current beside the terminal link.
- **Test helpers.** The app driver's `hold` gains `browser-on`, `browser-off` and `browser-status` through Settings' commands; the fake browser's `find` looks the manifest up where a browser looks and starts it as that browser does, on Windows through `%COMSPEC% /d /s /c` for the Chromium family.

## Limits and follow-ups

- **No real browser starts keypaste** until the extension exists and its IDs are in (8.1f, 8.1g, H-0029), and fill in real browsers is 8.3a3's.
- **Uninstalling keypaste leaves its manifests**, which the status reports as naming a `keypaste` that no longer exists; removing them at uninstall is a BACKLOG idea.
- **Another program's manifest under keypaste's name** is seen only when the status is read (T-49).
- **Settings offers no Turn off on another program's row**, so leaving one is shown through `keypaste browser off` and Core.
- **Existing pairings** made under KeePassXC-Browser's builds no longer check; browser fill was never released.
