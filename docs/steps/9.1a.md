# 9.1a — Define a loss-aware import pipeline

Completed 2026-10-28 on `t6-imp` in `e4aef79f` on `t6`, source only. At `8aabcf52`, ci 40777892604 and app 40777907585 passed every job on all three runners on their first attempt.

## Amendments

The founder decided on 2026-10-28 that an import writes an item's TOTP and its further web addresses as KeePassXC keeps them, in `otp` and `KP2A_URL_1`, `KP2A_URL_2` …, where this step had first named both as not imported under D-0369 and D-0477, and that a taken name is kept beside the other or skipped, with no Replace. D-0369, D-0477 and D-0498 are rewritten for it, and D-0565 says what lands. The row is otherwise as selected.

Its consumers here are a fake reader in the tests and `keypaste import`, which now hands a file that is no KeePass database to the reader that recognizes it. No reader ships (`ExportImport.Readers` is empty), so nothing a person runs changes and there is no CHANGELOG entry; the first reader to ship (9.1b) brings `import`'s help for exports and the entry.

An earlier draft on `draft/9.1a` (`36fa7e77`), never integrated or reviewed, listed the choices the row leaves open. This step follows its recommendations on keeping both items as the default for a taken name, a commit that saves, an untitled item and carrying a TOTP, which the founder's decision allows; it differs in offering no Replace, in carrying an item's times instead of naming them lost, and in wiring the CLI now.

## What changed

- **The contract** (`Core/Import/`). `IExportReader`, one per format: `Format`, `MaximumBytes`, `Recognizes(fileName, start)` over the file's first 4 KiB, and `Read(file)`, which returns `ExportContents`, the items and the records that are none (`ExportOmission`), or throws `ExportFormatException` naming a place and never a value. `ExportImport.Open(path, readers)` reads the file once into one buffer no larger than its reader takes and zeroes the buffer when the reader returns; it refuses a larger file before reading it, a file that grows while read, and a reader's failure, whose message it passes on only when it is the reader's own refusal (D-0565). `ExportItem` carries the standard fields, its folder, web addresses, custom fields (`ExportField`, protected unless the reader says plain), tags, a TOTP as an `otpauth://totp/` URI or KeeOTP's `key=` form, attachments (`ExportAttachment`, whose bytes the source zeroes when disposed), earlier versions (`ExportVersion`), its created and modified times and what the reader found on it and could not carry. Each type's `ToString` gives a name, never a value.
- **The preview.** `ExportSource.Plan(vault, into, decisions)` writes nothing. Items land under one group, the file's name unless the person names another, by the KDBX import's rule (now `ImportSource.DefaultInto`), each in its folders below it. A title or folder name keypaste would not write is made one: `/`, `\` and control characters become `-`, the ends are trimmed and an empty name is `untitled`; a folder named like the recycle bin lands as `Recycle Bin (imported)`; the row's note says why. The first web address is the item's URL and the rest land, plain, in `KP2A_URL_1`, `KP2A_URL_2` …; the TOTP lands, protected, in `otp` when `TotpSpec` reads it as written, so keypaste and KeePassXC compute its codes. Every part of a landing item that does not land is an `ExportLoss` with why: a field name `FieldNameRules` refuses or one given twice, a tag `TagRules` refuses, an attachment over D-0533's 5 MiB or under a name keypaste would not give one, a TOTP keypaste would refuse, with `TotpSpec`'s reason, and what the reader omitted; a record the reader read as no item is a loss of its own. A group that is keypaste's own, that bears the recycle bin's name, or that two groups answer to refuses the plan, as for a KeePass file (D-0565).
- **Collisions.** A name is taken when its group and title joined as a path are a live item's in the vault or an earlier item's of the export, the rule `Vault.CreateEntry` refuses a name by. The item is kept beside the other under the first free `title (2)`, `title (3)` … by default, or skipped (`CollisionDecision`, D-0566).
- **The commit.** `ExportSource.Commit(vault, plan, save)` plans again and refuses a plan that no longer matches the vault, takes `Vault.Checkpoint`, adds every landing item through `Vault.AddImported` and `KeePassInterop.AddImported` in one change with no history item of its own, its versions as its history oldest first and its own times, stamped a later second than every version (D-0387), then calls `save`, and restores the checkpoint when adding or saving throws (D-0567). Checkpoint and Restore are what `SessionEditor` already takes a terminal's edit back with when its save fails (D-0464). The caller passes its own save, so `keypaste import` saves as every verb does and 9.1f can save under the app's lifetime. `MarkEdited`'s stamping is now `StampAfter`, which the import shares.
- **The CLI** (`Commands/ImportFromExport.cs`). `keypaste import <file>` asks `CliContext.ExportReaders`, by default `ExportImport.Readers`, about a file that is no KeePass database, and refuses it as before when none recognizes it. An export needs `--vault` or `KEYPASTE_VAULT` and refuses `--in-place` and `--source-keyfile`; `--into` names the group. `--dry-run` prints each row and every loss on stdout under `VaultSession.Open`; otherwise the import is committed under `OpenHeld`'s claim and stderr says what was copied, each renamed or skipped item and every loss. `--skip-existing` skips each item whose name the vault already has and is refused for a KeePass file (D-0566). What is printed is sanitized and names items, fields and attachments, never a value.

## Limits and follow-ups

- **No KeePassXC gate reads an imported item yet.** That KeePassXC computes codes from the `otp` written and offers each `KP2A_URL_n` as a further web address rests on how KeePassXC stores them; the first reader's step can add the check to `verify-keepassxc-fields.sh`.
- `CHANGELOG`'s Unreleased TOTP entry says keypaste writes none of the TOTP fields; it stays true until a reader ships, and that reader's entry says what an import writes.
- **No Replace**, as the founder decided: a taken name is kept beside or skipped, and the vault's item is never overwritten by an import.
- **The KeePass import is unchanged.** `KdbxImportViewModel` still leaves copies whose save failed in the open vault, unsaved; moving it onto the same checkpoint is left to 9.1f. Closed in [9.1f](9.1f.md), through `ImportSource.Commit` (D-0593).
- **Values are strings.** An export's values live as strings until the source is dropped, as `VaultEntry`'s do (SECURITY.md); only attachment bytes and the file's buffer are zeroed.
- A field, tag or attachment the vault refuses by name is named, not renamed; a reader that can rename it better does so before the plan sees it.
- Source only.
