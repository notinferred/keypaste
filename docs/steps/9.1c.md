## What changed

- **The CSV reader** (`Core/Infrastructure/Csv.cs`), for this reader and 1Password's (9.1d2) and KeePassXC's (9.1e) to share. `Csv.TryRead(bytes, out records, out error)` gives every `CsvRecord(Line, Fields)` of a file or, as `line 7: …`, the first thing that is not RFC 4180: UTF-8 after an optional byte order mark, records ending in CRLF or LF, a bare field holding no quote, CR or LF, a quoted field in which `""` is a quote and a comma or line break is text, and every record as long as the first; a line with nothing on it is no record. `Csv.FirstRecord(start)` reads a header from a file's first bytes, up to its first line feed, for `Recognizes`. The decoded text is zeroed once read, no message holds a field's text, and a record's `ToString` gives its line (D-0573).
- **The LastPass reader** (`Core/Import/LastPassCsvReader.cs`), registered in `ExportImport.Readers`, read with LastPass's own command line, `lpass` (`cmd-export.c` and `notes_expand` in `blob.c`), and Bitwarden's `LastPassCsvImporter` as references. It recognizes a header naming `url`, `username`, `password`, `extra`, `name` and `grouping`, in any order, and reads `totp` and `fav` when present, so both the vault's export and `lpass export`, which writes no `totp`, are read; it takes up to 32 MiB. A site's `extra` is its notes and its `url` its web address. `grouping` is its folder, `\` between the names and `(none)` or empty for none, so a shared folder lands as `Shared-<name>` with its subfolders below. A row whose `url` is `http://sn` is a secure note: a plain one is its notes, and one whose text starts `NoteType:` is expanded as `notes_expand` expands it, each `name:value` line a protected field, a line with no colon continuing the value before it, as do the `Proc-Type:` and other lines of an SSH key's private key, and `Notes:` taking the rest; the type becomes a tag, `Username`, `Password` and `URL` the item's own, an empty value of LastPass's form nothing, and `Language`, the language of LastPass's form, is named as not imported (D-0572). A favorite gets the tag `Favorite` and a bare TOTP secret the link `otpauth://totp/<title>:<username>?secret=<secret>`, as KeePassXC's Bitwarden and 1Password importers make them (D-0574).
- **Everything that does not land is named.** A row whose `url` is `http://group`, which is how LastPass's data names an empty folder, and a row holding nothing are records of no item, with why; on an item, a column keypaste does not read that holds a value, a `fav` other than `0` or `1`, and `Language`. 9.1a's plan names the rest: a field name keypaste does not write, such as an address note's `Title`, and a TOTP secret `TotpSpec` does not read as written.
- **The CLI** (`Commands/ImportCommand.cs`). `keypaste import --help` gives the export form, `--skip-existing`, and the formats `ExportImport.Readers` reads.

## Limits and follow-ups

- **LastPass's export carries no attachments**, and nothing in the file says an item had one, so the preview cannot name them. Items shared with the person by someone else are not in the export either (LastPass's documentation).
- **Values are taken as written.** Exports from LastPass's older browser export were reported to write `&`, `<` and `>` as `&amp;`, `&lt;` and `&gt;`; keypaste cannot tell such a value from one holding that text, so it decodes nothing.
- **A typed note's values are all protected**, the ones LastPass shows openly included, since the export does not say which LastPass masks.
- **An address note's `Title`** is a KeePass standard name, so 9.1a's plan names it as not imported; the contract allows a reader to rename such a field, which this one does not.
- LastPass's form-fill profiles are a separate export with other columns, which no reader recognizes.
- No KeePassXC gate reads an imported LastPass item yet; that KeePassXC computes the codes from the `otp` link written rests on its importers building the same link (9.1a's limit).
- The desktop's import of an export is 9.1f.
