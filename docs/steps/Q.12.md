# Q.12 — Calm the reveal and the agent settings

Completed 2026-11-05 on `q12-reveal-and-settings`; ci 42032638872 passed its fast tier at the code integrated, which differs from it only in this record.

## Amendments

The row reverses D-0300: a reveal was held so a value was on screen only while somebody was deliberately holding it, which a person with a motor impairment, switch control or a screen reader's single activation cannot do. It is now a toggle, and T-25 and SECURITY say what that gives up: one click leaves a value drawn after the person looks away, for up to 30 seconds. The reveal's surface check (D-0232) is kept but no longer compares the whole window, since the row asks for a name that changes: everything outside the toggle stays equal at rest and revealed, and the sweep for the value still covers all of it.

On verifying the step, the coordinator removed the reveal on clicking a masked cell, which the first version kept from the hold for its wider target: a single stray click would put a secret on screen, and Env's cell then showed no Hide once the pointer left. A value now reveals only by its button, which every surface has and Tab reaches, and a click on a cell does only what it did besides: another environment's cell selects that environment. Env's caption names the button. The cell stays hit-testable, or Env's tooltip over a masked cell would stop answering.

Settled in the step, all reversible:

- 30 seconds. Long enough to read or retype a long value with a magnifier or switch control, which are who the toggle is for and who a shorter limit would fail, and within the limit of the brief. A value left there hides in half a minute. `RevealedValue.ShownFor` holds it, and `RevealedValue.ClockProperty`, an inherited attached property that defaults to the system's clock, lets a test set a `ManualClock` on a window.
- One value at a time across the app, in `RevealedValue.Shown`, beside each view model's slot, which stays. It is static because nothing else spans the Env screen, the pane and the dialogs; it runs only on the UI thread, holds a control and no characters, and clears with the reveal.
- Moving keyboard focus does not hide a value: a screen reader or a keyboard walking through the pane would lose it at the first Tab, and the row names the window's focus rather than the control's. Clicking Copy beside it leaves it shown.
- A value changed by a save while it shows is read again rather than hidden, through `IRevealSource.Changed`, which `EntryDetailViewModel.Reload` and `EnvVariableRow.Resize` now raise, so a cell never shows a stale value. A merge or a reload from disk hides it, whichever screen is open and whether or not it keeps a draft, through `ShellViewModel.VaultMoved`, which `ShellView` hands to `RevealedValue.HideShown`.
- Each cell's own accessible name no longer says what to do ("Hold to reveal the password"), because it is in no peer and would lie once revealed; it says what the cell is. `RevealLabel` left the rows, and `EntryRevisionRow.Subject` names the time.
- The toggle's word holds a minimum width so its neighbours stay put at "Hide". Its tooltip says "Reveal for 30 seconds" and "Hide", so an icon-only toggle keeps one that is true in both states.
- An Env row's actions show on hover or focus and, added here, for as long as the row's value shows, through a class the toggle sets on its parent, so its Hide never goes out of view with a value on screen. A long value, which ran on over the actions under the hold, now stops short of them (`KeepsClear`), which cuts it with an ellipsis sooner; Copy still has all of it.
- `MaskedInput`, the unlock screen and the prompts are unchanged. The row does not reach them: they are typing fields or release prompts with their own rules, and no prompt draws a `RevealedValue`.
- A segment that decides a setting is `ChoiceSegment`, a `ToggleButton` that does not check itself when pressed, because a change that gives an agent more waits on the prompt and a `RadioButton` would show it as made. The log's own filter and the tokens' expiry stay `RadioButton`s, whose choice takes effect at once. A chosen segment keeps its check mark from the old chips, so what holds is not colour alone, and its fill is `KpBgActive`, not amber.
- The theme's segment gained a focus ring, a 2px transparent border that its padding gives back so nothing moved, and a disabled state. The panel's segments are tighter than the log's (padding 6 against 10) and its label column is 120, so three modes fit on one line beside the sidebar at the narrowest the panel gets.
- **Give values sits behind More.** The row's acceptance opens on three controls and they exclude it, yet its second bullet does not list it behind More. It is the fourth control the panel has, and leaving it out of the three while visible would contradict the acceptance. More opens whenever it is No, so a setting away from the default is never hidden.
- More cannot be closed while a row, a pattern, a limit or Give values: No is set, or while a pattern or limit is being typed, and says so in a line. Opened by something set, it stays open when that is removed, rather than closing under the person's hand. "Advanced: patterns" is an `Expander` inside More with the same rule. A project row stacks its name above its segments, which no longer fit beside it.
- The picks under Only these are not drawn while the agent sees all projects, since they do nothing then. They are still many-of-several, so they stay buttons.
- Durations in words: the tokens' expiry reads 7, 30 and 90 days and the share dialog's list 1 hour, 24 hours and 7 days, with the view models and `--ttl` keeping `7d`. The toast "Expires in 24h" and the log's lifetimes keep `FormatTtl`, which the CLI and its transcripts share.
- `Expires` on the share dialog stays a segmented `ListBox`, and other choices of one, such as combo boxes in Settings, stay as they are: the row's list is the chips and ghost buttons that wrap.

## Limits and follow-ups

The row's cost on purpose: comparing a value beside another window is gone, because leaving the window hides it, so that takes a copy. No person has used this, nor a real screen reader, and no real window was opened, so `Window.Deactivated` on each platform, and a platform's own focus-stealing popup such as a native tooltip hiding a value early, are unverified; the headless tests call the window's deactivation directly. At the window's narrowest a long value on Env shows about a dozen characters before its ellipsis; Copy has all of it. Focus after a segment's choice goes where it went after a chip's, since the re-read rebuilds the list; BACKLOG holds it. The desktop gates, `compat` and the KeePassXC gates were not run. `DrawnMaskTests.A_shell_field_leaves_the_window_surface_the_same_for_any_value(name: "AccessConfirmPassword")` failed once on macos-15 in app run 42033914310 and passed on its rerun: the surface differed at position 10994, beside an `ItemsControl`'s `ItemCount`/`ItemsSource`, and `Assert.Equal` truncated which property, and returned before the exposure sweeps ran. The mechanism is unexplained; a background recommendations check finishing between the two snapshots is only a guess. Q.11 had the test name the first differing tuple and run both sweeps even when the snapshots differ, and asserts the same thing.
