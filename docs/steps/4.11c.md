# 4.11c — Report the app's crashes, with the terms at first run and Settings' switch

Completed 2026-10-28 on `t6-crash-app`, source only; runs pending.

## Amendments

The founder's decisions of 2026-10-28 selected the approved design's recommendations: the terms shown as a notice with Continue and two equal choices, Send crash reports and Don't send; Settings' switch showing and changing that choice; Diagnostics listing the reports waiting; the uptime bucket and the screen's name in each report; a UI-thread exception writing the report, locking, clearing the clipboard and quitting; the endpoint carried only by `app.yml`'s packages; and the legal entity left a marked placeholder until H-0027. Where the row and the design left detail open:

- **The notice and the choice.** The first start shows the terms with Continue, then the choice on a second step, its two buttons equal and neither the default, so Enter answers nothing (D-0594). A new date on the terms shows them again, and nothing is sent under them until it is answered.
- **What reads as on.** Only a `crash_reports = 1` in an `app.toml` that reads whole, beside the date of the terms this build carries. An `app.toml` that does not read whole shows no notice, so its answer would not replace a hand edit (D-0594).
- **A source build.** It keeps reports, which Diagnostics shows with a note that this copy sends none, and sends nothing unless `KEYPASTE_CRASH_URL` names a loopback server (D-0598).
- **The run marker.** It is kept beside the reports, holding only the version and the start's UTC time. A marker another version left is dropped rather than reported under the wrong version (D-0595).
- **The catch-all sites.** The design named Windows Hello among them; only `Sign`'s catch is reported, since `IsAvailable`'s failure is a Windows that has none. The owner's "could not be completed" reaches the app through `SessionAuthority.Unexpected`, which `keypaste approve` leaves unset (D-0596).
- **The terms text.** The draft's two marked options are resolved as decided, sending only after Send crash reports and no Cloudflare request logs, and "entry or group names" reads "item or group names", the app's word (D-0457, D-0597).
- **The exit code** of a run a UI-thread exception ends is 70.

## What changed

- **The run's crash reports.** `src/Keypaste.App/CrashReporting.cs`, which `Program.StartCrashReports` composes under the home's claim and the AppDriver's `launch` composes the same way, sets `AppDomain.UnhandledException` and `TaskScheduler.UnobservedTaskException`, keeps reports while on, sets and clears the run marker, turns an earlier run's marker into an `ended-unexpectedly` report, and starts the sender while on with an endpoint named. Reports carry the screen as the places are named (`items`, `agents`, `settings`, `first-run`, `unlock`, …) and the uptime from the start.
- **A UI-thread exception.** The app's `OnFrameworkInitializationCompleted` sets `Dispatcher.UIThread.UnhandledException`. `EndAfterCrash` marks the exception handled, keeps its report, locks the vault, gives back the shell's clipboard, quits through the orderly path and ends with exit code 70. A second exception while it ends is only reported.
- **First run.** `Terms/terms-of-use.txt`, embedded in the app, is the one copy of the terms; `TermsOfUse` reads it, leaving out the `//` notes that mark it a draft pending H-0027. `FirstRunView` stands in front of the unlock screen, which is built behind it, so a locked notice still finds the vault it shows.
- **Settings and Diagnostics.** Settings has a Crash reports card with the Send crash reports switch, and turning it off deletes `~/.keypaste/crash-reports/`. Diagnostics lists each report waiting as its exact JSON, with Delete, and says when the switch is off or the build sends none.
- **Core.** `AppSettings` reads and writes `crash_reports` and `terms`. `CrashOutbox` keeps the run marker (`MarkRunning`, `ClearRunning`, `TakeEndedRun`), which `Tidy` leaves and `Clear` takes. `SessionServerOptions.Unexpected` reaches `SessionAuthority.Unexpected`.
- **The endpoint.** `app.yml`'s package publish passes `-p:KeypasteCrashEndpoint=https://keypaste.com`, which `Keypaste.App.csproj` writes as assembly metadata.
- **The gate.** `scripts/verify-crash-report.sh` joins the desktop-gates profile, and `app.yml`'s push paths take it and the linked `FakeCrashServer.cs`. The AppDriver's `launch` gains the lines `first-run`, `unlock`, `copy`, `lock`, `crash` and `unobserved`, a clipboard that says when a secret lands and is cleared, and the `crash-endpoint` act, a loopback stand-in for `/api/crash` that answers 204 or never answers.
- **The installed-app exercises.** `exercise-desktop-install.sh`, `exercise-desktop-upgrade.sh` and `exercise-desktop-acts.sh` press Continue and Don't send on a fresh home's first start. R.1a's first-run act then records `crash_reports = 0` and finds Diagnostics saying none are kept; its selftest gains two cases.

## Limits and follow-ups

- The installed-package act runs only in `install-desktop.yml` on a packaged candidate, which this step did not run. The acts and the install and upgrade exercises now step through the first run, and their next run is its evidence.
- An exception off the UI thread still ends the process as the runtime ends it, leaving a copied value on the clipboard. The gate does not crash a thread, since a process that dies so can wait on Windows Error Reporting; `CrashReportingTests` runs the hook's handler.
- An unclean exit reported from its marker is a weak signal: power loss and a forced logout leave one too. A run that ends so under one version and starts under another is not reported.
- The terms are a draft until H-0027, and the route answers 503 until H-0028. A package now sends to keypaste.com while the switch is on, and a 503 keeps reports waiting with the sender asking again after a day.
- Whether the first-run choice satisfies EU consent law is H-0027's to decide.
