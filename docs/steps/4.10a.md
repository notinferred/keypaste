## What changed

- **Two targets.** `Keypaste.App` builds `net10.0`, which the Linux and macOS packages carry, and `net10.0-windows10.0.19041.0`, which the Windows package carries and which alone reaches Windows Hello, through the Windows SDK's WinRT projection the pinned SDK selects (D-0549). `EnableWindowsTargeting` lets the macOS compile check build both. `app.yml` and `build-upgrade-candidates.sh` publish the Windows target for `win-x64` and the plain one elsewhere, `verify-session-lifecycle.sh` starts the app from its target's folder, and `tests/Keypaste.App.Windows.Tests`, which `dev.yml` maps, runs against the Windows target. The CLI, the bridge and their lock files do not change.
- **Key parts in Core.** `VaultKeyParts` holds what `Vault.ExportKeyParts` reads from an open vault's key: the master password's SHA-256 as `KcpPassword` holds it, the keyfile's key and its path, and a hardware key's slot, never its answer; disposing zeroes them. `Vault.Open(path, parts, hardwareKey)` rebuilds the key in `KeePassInterop` with `KcpCustomKey(name, data, false)` parts in a password unlock's order, so the composite key is the same, and asks the hardware key again. The interop finds a password or keyfile part whether typed or rebuilt, so a vault opened from its parts reports its password and keyfile, reloads and changes its access as a typed unlock does.
- **Sealed copies.** `Session/QuickUnlockCopies.cs` seals the parts with `AesGcm` under the SHA-256 of a signature over a fresh 32-byte challenge, with a 12-byte random nonce and the vault's identity as associated data, and keeps them by that identity in memory only. A copy whose signature no longer opens it is dropped; a forget counts, so a keep whose parts were read before a forget stores nothing (D-0550).
- **The session.** `AppVaultSession.KeepForQuickUnlock` reads the unlock's parts and has the copies keep them; `TryResume` takes the vault's claim, refusing a vault held elsewhere before anyone is asked, opens the copy and the file, and drops the copy when the file's key changed. `Lock` drops it for every reason but `Idle`, `Manual`, `Minimized` and `Closed`, under the gate once the vault is detached, as does another vault opened in its place, a written access change and quitting (D-0551). The reopen after an access change is `ReopenAfterAccessChange`, for V.1b's test.
- **Windows Hello.** `Session/WindowsHello.cs`, compiled only into the Windows target, reports availability with `KeyCredentialManager.IsSupportedAsync`, opens or makes the key `keypaste`, signs with `RequestSignAsync`, and for two seconds looks for the `Credential Dialog Xaml Host` window to put in front, as KeePassXC does; any WinRT failure reads as unavailable or failed. `QuickUnlockSigners.ForThisMachine` gives it on Windows 10 2004 or later and nothing elsewhere, and `App.QuickUnlockSigner` composes it.
- **The unlock screen.** A password unlock, and a restored backup's, wait for Windows Hello's answer before the shell shows, under "Confirm with Windows Hello so it can unlock this vault after a lock." (D-0552). A vault with a copy shows Unlock with Windows Hello, with Lucide's fingerprint icon, as the screen's one amber action above the master password, whose field and Unlock button stay; the subtitle names both, and Enter in the empty field asks Windows Hello. A cancel says nothing, and an unavailable or failing Windows Hello, a changed key and a copy that no longer opens each say what to do (D-0553). A screen a lock replaced while Windows Hello asked hands the vault over only while the unlock is still the session's own.
- **V.1b's limit.** `VaultAccessTests` shows a reopen that throws after a written password change answering `ChangedAndLocked`, locking with `AccessChanged`, the screen showing `AccessChangedMessage` through `App.LockMessage`, and the new password opening the vault.
- **N.6's limit.** `PlainWordsTests` sweeps the welcome with and without KeePassXC's databases, the lock screen with More options open, with Windows Hello offered and after an access change, the create form, and the KeePass database import dialog unreadable, locked, refused, decrypted and kept in place.
