A password manager your agents have to ask.

keypaste keeps your logins and your projects' environment variables in one ordinary KDBX file on your disk. When an AI agent needs a credential, it asks for one field; you read who is asking and why, and you approve or deny that request (the next release adds allowing it once or for an hour).

01

One vault, two jobs

The same file holds the passwords you type and the secrets your code runs with. Nothing about it is special to keypaste: KeePassXC opens it too.

Your passwords

Logins with a username, password and URL, filed in groups, in the KDBX format KeePassXC opens. get copies a password to the clipboard and clears it after twenty seconds; it prints the value only when you pass --show.

keypaste add github --username me --url https://github.com
keypaste get github

The desktop app, for browsing, editing and restoring entry history, runs from source and has no public download yet.

Your projects and their agents

A project's variables are entries under env/<project>. keypaste run injects them into one child process, and an agent asking over MCP gets one field, only after you approve it or a rule you wrote covers it. Every request is logged locally, granted or refused.

keypaste env pull dev
keypaste run dev -- npm start

keypaste does not revoke a credential at its provider, and a value an agent already received stays with that agent.

02

Sixty seconds, end to end

An agent asks for one credential, a person approves it, the deploy runs and the audit log records it. The demo script has every step.

03

What it is, and what it is not yet

Local-first, offline

Your vault is a file on your disk. Local use needs no account, service or network. Existing file-sync tools can transport the encrypted file; keypaste has no merge or managed-sync workflow.

Standard KDBX, not a new format

CI checks KDBX read/write compatibility against real keepassxc-cli on Linux, macOS and Windows on qualifying pushes to main and every pull request. Your file remains portable; this does not claim complete KeePassXC feature coverage.

Open source, AGPL

Auditable by anyone. A tool that handles secrets should not ask to be trusted on faith.

Published: CLI/MCP v0.3.0. Local vaults, environment injection and terminal approval are available on four native targets. The binaries are unsigned and there is no public desktop download. In source, the desktop and keypaste agent share one owner per vault, keypaste lock locks whichever holds it, and the Env profiles screen launches a project's command or a terminal from the unlocked session; none of this is published.

04

Install

Five lines, and the third one is the reason the other four are worth typing: it checks the archive against a hash published beside it and stops if they disagree. Each binary is a single native file, so nothing needs .NET on your machine.

macOS · Apple Silicon
curl -fLO https://dl.keypaste.com/v0.3.0/keypaste-0.3.0-osx-arm64.tar.gz
curl -fLO https://dl.keypaste.com/v0.3.0/keypaste-0.3.0-osx-arm64.tar.gz.sha256
shasum -a 256 -c keypaste-0.3.0-osx-arm64.tar.gz.sha256
tar -xzf keypaste-0.3.0-osx-arm64.tar.gz
mkdir -p ~/.local/bin && mv keypaste keypaste-mcp ~/.local/bin/

macOS 14 or later. That floor is what .NET 10 supports rather than a version this project has measured, so no run backs this floor.

Linux · x64 and arm64
curl -fLO https://dl.keypaste.com/v0.3.0/keypaste-0.3.0-linux-x64.tar.gz
curl -fLO https://dl.keypaste.com/v0.3.0/keypaste-0.3.0-linux-x64.tar.gz.sha256
sha256sum -c keypaste-0.3.0-linux-x64.tar.gz.sha256
tar -xzf keypaste-0.3.0-linux-x64.tar.gz
mkdir -p ~/.local/bin && mv keypaste keypaste-mcp ~/.local/bin/

For arm64, substitute linux-arm64 in all three filenames. glibc 2.35 or later: Debian 12, Ubuntu 22.04 and newer. The release workflow runs the x64 binary on a clean Debian 12 and requires Alpine to refuse it; the equivalent container check is not implemented for arm64.

Windows, Intel Macs, Alpine and building from source are in the README. There is deliberately no curl | sh: it asks you to run code you have not read, from an origin that is not the repository. The checksum proves the bytes arrived intact, not who made them: it is served from the same origin as the archive, so anyone who can replace one can replace both. The binaries are unsigned. Source-build instructions and the v0.3.0 build-attestation procedure are in the README.

Then a vault, and a project with no .env in it:

~/project
keypaste init ~/vault.kdbx
export KEYPASTE_VAULT=~/vault.kdbx

keypaste env pull dev            # imports ./.env, then offers to delete it
keypaste run dev -- npm start    # injected into the child process, nothing on disk
05

Connect an MCP client

The current CLI workflow uses two processes. keypaste-mcp is started by your MCP client and forwards requests without opening the vault. keypaste agent is started by you, holds the vault, and asks you the question at the top of this page.

keypaste agent --vault ~/vault.kdbx

The downloads above are v0.3.0, which includes setup: it finds installed clients and configures each through its own mcp add, and a client without one gets its block printed to paste. Only v0.1.0 lacks it; on that release use the manual client instructions instead.

keypaste setup --vault ~/vault.kdbx

Nothing keypaste writes into a client's configuration holds a master password, and nothing ever will. MCP tool calls are logged locally, granted or refused. The bridge excludes the returned field value, but request names and reasons remain and may contain sensitive text:

keypaste log
  time (UTC)           client       entry                decision  method
  2026-07-26 14:03:09  claude-code  -                    granted   exposure
  2026-07-26 14:03:11  claude-code  env/demo/STRIPE_KEY  granted   prompt
  2026-07-26 14:07:44  claude-code  env/demo/STRIPE_KEY  denied    out-of-scope
06

Running an older version?

Published versions are never rewritten here, so the old archives are still served and still broken. Replacing the binary is the fix. Full detail is in the changelog.

IF YOU HAVEWHAT IT DOESFIXED IN
0.1.0 Can destroy your vault: env export can delete your vault, writing a project's variables over it in plaintext and taking every other entry and its history. Also: env rm and env set can act on the wrong entry; get can return the wrong password; env pull can delete an edit it never imported; and moving the clock back can revive an expired approval. 0.2.0
0.2.0 Can lose an edit: saving while another program saves the same vault can undo its change, with the lost edit in no history and nowhere else. Two saves within about two seconds was enough, which is what a password manager and an agent sharing a vault do. Two more that lose nothing are listed in the changelog. 0.3.0
07

The desktop app

The next release focuses on daily vault use and recovery, one unlock session, native MCP approvals that allow a request once or for an hour, and launching a project with its env set. Locking will stop new session-backed secret releases and launches. Values already delivered to an agent or child process remain outside that control. Share links that open once by default (up to 10 times) come with the CLI; keypaste.com serves them once sharing is switched on. Hosted sync, accounts, teams and complete KeePassXC parity stay out.

Tell me when the app ships. The CLI/MCP is available above. The intended desktop app uses one unlock session for credentials, native approvals and project launches; it has no public download yet.
