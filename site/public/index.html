That is the whole product in one screen. An agent asked; you were shown who, what and why; one field goes back for a lifetime you were told about. Watch it end to end — about sixty seconds.

Stop pasting secrets into chats. keypaste is a local-first, KDBX-compatible vault that stores your passwords and env variables, injects them into your projects, and lets AI agents like Claude request exactly one credential — with your approval, scoped access, and a full audit trail — without ever seeing your vault.

For developers who are tired of choosing between .env files and trusting an agent with everything.

  • Local-first, offline Your vault is a file on your disk. No account, no cloud service holding your secrets, no network required. Sync it yourself with whatever you already use.
  • Standard KDBX, not a new format Everything keypaste writes opens in KeePassXC and KeePass, proved in both directions against a real keepassxc-cli on Linux, macOS and Windows on every push. If keypaste disappears tomorrow, your data doesn't.
  • Open source, AGPL Auditable by anyone, forever. A tool that handles secrets shouldn't ask to be trusted on faith.

Pre-1.0, and it says so. The vault, the environment-variable injection and the agent bridge all work today and are tested on all three operating systems. The binaries are unsigned, the desktop app is not released yet, and the approval prompt is a terminal prompt rather than a native dialog.

Install

Five lines, and the third one is the reason the other four are worth typing: it checks the archive against a hash published beside it and stops if they disagree. Each binary is a single native file, so nothing needs .NET on your machine. macOS on Apple Silicon:

curl -fLO https://dl.keypaste.com/v0.1.0/keypaste-0.1.0-osx-arm64.tar.gz
curl -fLO https://dl.keypaste.com/v0.1.0/keypaste-0.1.0-osx-arm64.tar.gz.sha256
shasum -a 256 -c keypaste-0.1.0-osx-arm64.tar.gz.sha256
tar -xzf keypaste-0.1.0-osx-arm64.tar.gz
mkdir -p ~/.local/bin && mv keypaste keypaste-mcp ~/.local/bin/

Linux x64 — substitute linux-arm64 for arm64:

curl -fLO https://dl.keypaste.com/v0.1.0/keypaste-0.1.0-linux-x64.tar.gz
curl -fLO https://dl.keypaste.com/v0.1.0/keypaste-0.1.0-linux-x64.tar.gz.sha256
sha256sum -c keypaste-0.1.0-linux-x64.tar.gz.sha256
tar -xzf keypaste-0.1.0-linux-x64.tar.gz
mkdir -p ~/.local/bin && mv keypaste keypaste-mcp ~/.local/bin/

Windows, Intel Macs, Alpine and building from source are in the README. There is deliberately no curl | sh: it asks you to run code you have not read, from an origin that is not the repository. And the checksum proves the bytes arrived intact, not who made them — it is served from the same origin as the archive, so anyone who can replace one can replace both. The binaries are unsigned. Building from source is strictly stronger and is documented permanently.

Then a vault, and a project with no .env in it:

keypaste init ~/vault.kdbx
export KEYPASTE_VAULT=~/vault.kdbx

keypaste env pull dev            # imports ./.env, then offers to delete it
keypaste run dev -- npm start    # injected into the child process, nothing on disk

Connecting it to Claude

Two processes, and the split is the whole design. keypaste-mcp is started by your MCP client, holds no vault and decides nothing. keypaste agent is started by you, holds the vault, and asks you the question at the top of this page.

keypaste agent --vault ~/vault.kdbx

Then point Claude Desktop at the bridge — paths must be absolute:

{
  "mcpServers": {
    "keypaste": {
      "command": "/absolute/path/to/keypaste-mcp",
      "args": [
        "--vault", "/absolute/path/to/vault.kdbx",
        "--client-label", "claude-desktop"
      ]
    }
  }
}

There is no place in that config for a master password, and there never will be. Every call an agent makes — granted or refused — is one line in a log on your disk, and the value is never in it:

  time (UTC)           client       entry                decision  method
  2026-07-26 14:03:09  claude-code  -                    granted   exposure
  2026-07-26 14:03:11  claude-code  env/demo/STRIPE_KEY  granted   prompt
  2026-07-26 14:07:44  claude-code  env/demo/STRIPE_KEY  denied    out-of-scope

keypaste is not the only thing in this space, and pretending otherwise would be the fastest way to lose the argument. Keeper's MCP server prompts a human before it returns unmasked secret data. Bitwarden published an Agent Access SDK in March 2026 with the same request-and-approve shape, though it is alpha and its logging is not there yet. 1Password's Environments MCP server asks for approval too, and then deliberately never hands the credential over at all — a different answer to the same problem, not a worse one. What is keypaste's is the combination: an ordinary KDBX file you own, no account and no server anywhere, a person answering each request, and a log that never leaves your disk.
