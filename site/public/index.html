Scattered secrets, gathered in one place you own.

Passwords in one app, API keys in old chat threads, a .env file in every project. keypaste keeps them in one standard KeePass file on your computer, with no account, and runs a project with its values without writing a .env file. KeePassXC opens the same file.

Available nowVerified requesters · Coming in 1.0

Agents get only what you allow.

An AI agent asks for one field and says why. You answer, keypaste hands over that field and nothing else, and every request is logged, allowed or refused. In 1.0 keypaste also checks which program is really asking.

Share links · Coming in 1.0Team projects · Planned

Share with your team without passing secrets around.

A password sent in a chat message stays in that chat. In 1.0 a share link carries one field or one login, sealed on your machine, and opens only a set number of times. Next, a project's environments are shared with your team through a relay that stores only ciphertext.

Planned

Work access that belongs to the organization.

When work credentials live in personal accounts, they leave with people. Planned for organizations: work vaults the company owns, with keypaste recommending that every login on the company's email move into them. Revoking someone's access hands their work vaults to the right person instead of losing them, and no server ever reads anyone's personal vault. Single sign-on, provisioning, approval for production changes and audit export come with it.

Reach a server without handing out VPN configs.

Today reaching a private server usually means giving someone a WireGuard config, which keeps working until somebody remembers to revoke it. We are exploring how keypaste could grant that access to a person and take it back as simply as a shared project. It is a direction, not yet a plan.
