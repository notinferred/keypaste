keypaste protects your secrets at rest in an encrypted KDBX file, and it stands between your secrets and every AI agent that asks for one. It does not protect against a machine that is already compromised. [SECURITY.md](https://github.com/notinferred/keypaste/blob/main/SECURITY.md) owns the exact guarantees and the current release's known limits, and [THREATS.md](https://github.com/notinferred/keypaste/blob/main/THREATS.md) owns the threat model, threat by threat. This page describes the build headed for 1.0.0; SECURITY.md says which guarantees also hold for the published `v0.3.0`.

## What it protects

- **The file.** A copied vault is ciphertext under KDBX 4 with Argon2 and AES-256. How long it resists guessing depends on your master password, and a key file or a YubiKey can add a second factor.
- **The approval.** No agent can trigger your master-password prompt or read the vault. A request releases one field or one attachment; a command an agent asks to run, which you approve, gets one project's set in its environment. You see who asks, for what and why before anything is released, unless you allowed that kind of value for every agent or always allowed it for that agent, each a change you confirm first; each such release is still recorded.
- **The record.** Every agent request leaves a line in a local, hash-chained log that `keypaste log verify` checks.
- **Share links.** `keypaste share`, in the 1.0.0 build, seals a value on your machine and uploads only ciphertext to keypaste.com; the key travels in the link.
- **Your disk.** Project runs put values in a program's environment and write no plaintext file. Only `keypaste env export --dotenv`, which you run yourself, writes values in plain text.

## What it cannot

- **Programs running as you.** Anything running under your user account can read memory, files and keystrokes. That includes an AI agent with its own shell, which can also reach the agent's own configuration and a running program's environment. THREATS.md lists each case.
- **Anyone who can open the vault.** This computer's agent rules are sealed with a key the vault holds, so a program that holds the unlocked vault can write rules keypaste follows without asking you.
- **A value already released.** Whoever received a value keeps it. Removing an Always allow stops further releases, not the copies.
- **The issuing service.** keypaste cannot revoke a credential at the service that issued it.
- **The log's history.** The audit log shows edits but cannot prevent them, and removing its last lines goes unnoticed unless you keep a copy of its latest hash elsewhere.

## Report a problem

Send anything that looks like a security problem to security@keypaste.com rather than the issue tracker. SECURITY.md says what happens next and how fast.
