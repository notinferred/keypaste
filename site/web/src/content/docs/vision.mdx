keypaste starts with one person and the KeePass file they already have: logins and project secrets in one vault, programs run with their variables, and AI agents that have to ask. After the first desktop release it grows in two directions. An agent gets to use a credential without ever holding it. And a team shares a project's secrets through a relay that stores only ciphertext, with identities for CI and deploys and single sign-on for organizations.

Two things never change on the way. No keypaste server will ever be able to read a secret, and local use will never need an account or a network.

## What stays out

- A server that can read your secrets, and everything that needs one: PKI, KMS, privileged-access management and dynamic secrets.
- Syncing your whole vault through keypaste. Your own file sync and the KeePass apps you already use carry it.
- Phone and web vault apps.

The [roadmap](https://github.com/notinferred/keypaste/blob/main/ROADMAP.md) owns the order of this work, and [PRODUCT.md](https://github.com/notinferred/keypaste/blob/main/docs/PRODUCT.md) owns the commitments behind it.
